# v13.9 — v13.8 검토 반영

2026-09-25. v13.8 검토에서 나온 수정 권장 3건과 사소한 문제 2건을 모두 수정했다. v13.8의 기능과 저장 형식은 그대로 유지한다.

## 1. 선행 준비 범위와 이미지 동시 요청 (P2)

**문제:** v13.6부터 현재 턴과 새로 도착한 턴의 모든 공개 문단을 미리 준비했다. 대기열의 동시 3개 제한은 인물 배치 확인에만 걸리고, 이미지 생성은 대기열 밖에서 제한 없이 나갔다. 문단 6개(각 인물 1명·절정 비트 1개), CG 켬, 독자가 1문단에 머문 상태에서 이미지 요청 19건(사건 CG 6장), 동시 요청 최대 7건이 나갔다.

**수정:**
- 준비 단계를 나눴다(`preparationTier`).
  - 읽는 문단: 배경·인물·표정 + 사건 CG
  - 다음 2개 문단: 배경·인물·표정(CG 없음)
  - 그 이후: 인물 배치 확인과 이미 저장된 이미지 불러오기만(유료 이미지 생성 없음)
- 독자가 문단을 넘어가면 해당 문단이 다음 단계로 올라가 다시 준비된다.
- 사건 CG는 독자가 그 문단에 도달했을 때만 만든다.
- 유료 이미지 요청은 동시에 최대 2건(FIFO)으로 제한한다(`maxConcurrent`). 한꺼번에 몰려 사용량 한도(429)에 걸리고 실패가 남는 일을 줄인다.

**결과(같은 조건):** 인물 배치 확인 6건, 입상 3건(읽는 문단 + 다음 2개), 사건 CG 1건, 동시 이미지 요청 최대 2건.

## 2. 현장 인물 신원 확인의 오판 (P2)

**문제:** 신원 근거 문장에 `기억`, `떠올`, `살던` 같은 단어가 어디에든 있으면 인물을 무대에서 뺐다. 따옴표 안에서 부르는 이름은 인정하지 않았고, 이름이 3600자 창 밖으로 밀려나면 신원을 확인할 수 없었다. 입상은 빠지는데 이름표는 남았다.

**수정 (`vn-cast.mjs`):**
- 간접 표현은 **그 이름을 실제로 꾸미는 경우에만** 신원을 부정한다(`directIdentity`).
  - 이름 앞: `사진 속`, `기억 속`, `故`, `돌아가신`, `실종된` 등
  - 이름 뒤 같은 절: `실종`, `사망`, `살던`, `남긴 편지` 등
  - 목적어로 회상: `나디아를 떠올렸다`
  - 예: "나디아가 문을 열고 들어오며 그날의 기억을 떠올렸다", "내가 살던 동네 골목에서 나디아가", "나디아는 그 일을 기억했다"는 이제 신원으로 인정한다.
- 대사 속 부르는 말("나디아, 여기야", "나디아 씨!")을 신원 근거로 인정한다(`vocativeIdentity`).
- 이름이 3600자 창 밖에만 있으면, 창 밖에서 그 인물을 마지막으로 직접 부른 문장을 `anchors`로 함께 보낸다(`identityAnchors`). 대명사로 이어지는 인물의 신원을 인용할 수 있다. 현장 등장 근거는 여전히 따로 필요하다.
- 화자 서술("나디아가 말했다")도 신원 근거로 인정하고, 화자 이름표의 존칭("연구자님", "나디아 씨")을 떼고 비교한다.
- **이름표와 입상은 같은 기준을 따른다.** 확인되지 않은 후보의 이름은 이름표에도 쓰지 않는다. 등록되지 않은 일반 호칭("교수")은 지금처럼 이름표로 보인다.
- 캐시: 앵커가 필요 없는 문단은 v13.8과 같은 인물 배치 키를 써서, 이미 비용을 낸 결정을 다시 요청하지 않는다. 새 규칙은 저장된 결정을 읽을 때도 적용된다.

## 3. 표정 이미지가 감정 분류와 어긋나는 문제 (P2)

**문제:** 표정 이미지는 `smile` 같은 감정 분류로 저장·재사용되는데, v13.5 프롬프트에는 그 감정이 없었다. 첫 장면이 쓴웃음이면 굳은 얼굴이 `smile` 칸에 저장되어 이후 모든 미소 장면에 쓰일 수 있었다.

**수정 (`vn-assets.mjs`):**
- 프롬프트에 **필수 감정**을 넣었다. 예: "at a glance the face must clearly read as a warm, genuine smile". 본문 맥락을 바탕으로 모델이 자연스러운 반응을 정한다. 사용자의 기존 요청에 맞춰 미간·턱·입 모양을 강제하는 지시는 배포 검토에서 제거했다.
- 새 저장 키 `vn-story-expression-2`. v13.5~v13.8의 표정(`-1`)과 그 이전 표정은 새 이미지가 준비될 때까지 대체 이미지로만 쓴다. **필요한 표정마다 한 번 새로 생성된다(이미지 비용 발생).** 배경과 기본 입상은 그대로 재사용한다.
- 비교 화면(`/image-compare`)은 감정을 지정하지 않으므로 기존 프롬프트 그대로다.

## 4. 새로고침 후 NVL 이전 줄 화자 이름표 (P3)

`speakerOf`가 메모리 기록에 없는 줄은 그 줄의 인물 배치 결과(`assets.view`)로 화자를 다시 구한다. 새로고침 뒤 이어 읽어도 같은 묶음의 이전 대사 줄에 이름이 표시된다.

배포 검토에서 다음 문단으로 넘어간 뒤 새로고침할 때 이전 문단 이름표가 빠지는 경우도 재현했다. 화면에 남아 있는 이전 문단의 저장된 인물 판정을 읽어서 복원한다. 이 복원은 캐시만 읽고 모델을 호출하지 않는다. 캐시 복원 중 해당 문단으로 돌아가는 경우에도 필요한 현장 확인이 누락되거나 중복 호출되지 않도록 처리했다.

## 5. 인물 확인이 불가능할 때의 화자 (P3)

인물 배치 확인이 실패(`error`)했거나 본문 키가 없을(`needs-key`) 때만 작가 주석의 화자를 **임시 이름표**로 표시한다(흐린 기울임꼴, 설명 툴팁). 입상에는 연결하지 않는다. 확인 중(`checking`)에는 추측하지 않고, 확인이 끝나면 확인된 화자로 바뀐다.

## 배포 전 추가 검토·수정

- 과거 신원 앵커가 현장 등장 근거나 현재 화자의 근거로도 인정되는 오류를 재현했다. 앵커는 신원 확인에만 쓰고, 등장·화자는 현재 문단과 직전 3600자에서 근거를 찾도록 수정했다.
- 두 가지 오인 재현 테스트는 수정 전 실패하고 수정 후 통과했다. 오래된 이름과 현재 등장 근거를 함께 쓰는 정상적인 대명사 연결은 유지된다.
- 표정의 감정 분류와 얼굴을 새로 그리는 방식은 유지하면서 얼굴 부위의 구체적 조작 지시를 제거했다.

## 제공된 ZIP의 검증 기록

- Node 테스트 200개 통과(v13.8의 190개 + 신규 10개), `tsc --noEmit`, `npm run build` 성공.
- 신규 테스트: 준비 단계별 이미지·CG 수와 동시 요청 상한, 준비 단계 규칙, 간접 표현 5종과 직접 신원 3종, 부르는 말, 3600자 앵커와 키 호환, 이름표·입상 일관성, 필수 감정 프롬프트, 이전 표정의 대체 표시와 새 표정 1회 생성, 임시 화자 규칙.
- 브라우저 fixture(합성 이미지·응답)에서 v13.8과 v13.9를 같은 절차로 비교했다.
  - 3/7까지 읽고 새로고침: v13.8은 이전 대사 줄 이름표가 사라지고, v13.9는 "나디아"가 유지된다.
  - 인물 확인 실패: v13.8은 화자 없음, v13.9는 임시 이름표 "나디아?", 입상 없음.
  - 전체 흐름(비, 2인 배치, 클로즈업, 사건 CG)에서 페이지 오류 없음.
- 실제 유료 모델은 호출하지 않았다. 필수 감정을 넣은 뒤의 실제 그림 품질과, 실제 모델 출력에서 신원 확인이 얼마나 정확한지는 실사용 확인이 필요하다.

## 배포 검토에서 직접 수행한 검증

- 기존 전체 테스트와 추가 회귀 테스트 총 203개 통과, 타입 검사 통과, 배포 빌드 성공.
- 합성 응답을 사용하는 로컬 브라우저에서 같은 문단과 다음 문단의 읽던 위치 복원·이전 대사 이름표를 확인했다. 이름표 복원 전후 인물 판정 요청 2건, 입상 요청 1건, 배경 요청 1건으로 추가 호출이 없었다.
- 저장 실패를 모사해 선택지 잠금과 복구 버튼을 확인했고, 복구 후 선택하면 BEAT 02의 다음 턴이 표시되는 것을 확인했다.
- 실제 유료 모델과 사용자의 실제 저장 데이터는 이 검토에서 호출·수정하지 않았다. 이미지 품질과 실제 API 키의 사용 가능 여부는 이번 검증 범위에 포함하지 않는다.
