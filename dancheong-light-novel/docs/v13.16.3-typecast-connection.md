# v13.16.3 — Typecast 연결과 오류 복구

## 변경

- Typecast를 선택한 뒤 키를 저장하면 필요한 캐릭터 목록도 자동으로 불러옵니다.
- 별도 **키 저장·연결 확인** 버튼은 Typecast 키만 기기 키 보관함에 저장하고 캐릭터 목록을 조회합니다. 다른 공급자 키는 유지합니다. 음성을 생성하지 않으므로 이 확인에는 음성 생성 크레딧이 들지 않습니다.
- AI 음성 ON/OFF는 계속 사용자가 선택합니다. 연결 확인만으로 유료 음성을 켜지 않습니다.
- 인증 실패, 권한 부족, 크레딧 부족, 요청 제한 등 음성 서버가 반환한 안내를 플레이 화면에 표시합니다. 403은 공급자의 짧은 구조화된 사유도 표시하며, 키·입력 대사·원본 응답 전체는 노출하지 않습니다.
- 설정 저장/연결 성공 시 실패 기록을 초기화해 같은 대사를 재시도할 수 있습니다. 이전 키의 늦은 실패가 새 요청에 섞이지 않습니다.
- 이미 성공한 음성은 유지합니다. 설정을 수정하는 동안 성공한 요청도 다시 구매하지 않고 재사용합니다.
- Typecast가 `UNUSUAL_ACTIVITY_DETECTED`를 반환하면 한국어로 사유를 안내하고 현재 탭에서 추가 Typecast 자동 합성을 중단합니다. 저장된 음성은 계속 재생할 수 있으며, 계정 제한 해결 뒤 사용자가 다시 시도를 누르거나 연결 설정을 저장하면 재시도합니다.

## 확인

- 플레이 화면의 작은 **Typecast · 음성 출처** 버튼과 음성 설정의 출처 문구·공식 링크를 추가했습니다. 실제 재생에 성공한 Typecast 목소리의 공개 이름을 작품별로 누적해 표시합니다. 합성 실패, 다른 공급자, 샘플 미리듣기는 작품 출연진에 넣지 않습니다. 키·대사 내용은 출처 기록에 저장하지 않습니다. https://typecast.ai/kr/guideline/ 의 3가지 표기 항목을 반영했습니다.

- 외부 Chrome의 실제 계정에서 캐릭터 목록 608개 조회 성공. 기존 설정은 AI 음성 OFF, Typecast 선택, 미연결 목록 상태였습니다.
- 음성 ON 적용 후 실제 대사 합성에서 `403 / UNUSUAL_ACTIVITY_DETECTED`가 재현됐습니다. 계정 대시보드는 무료 API 플랜, 사용 0/15,000 크레딧을 표시했습니다. 현재 발급 키 재연결 뒤에도 같은 차단이 확인됐습니다. 목록 조회 성공과 실제 합성 허용 여부는 별개이며, 잔여 크레딧만으로 재생 가능 여부를 판단하지 않습니다. Typecast 측 계정 확인이 필요하며 실제 합성 성공은 아직 검증하지 못했습니다.
- 자동 검증: 키/목록 검증, 빈 목록 거부, 오류 메시지 및 키 가림, 설정 변경 후 같은 대사 복구, 이전 요청 실패 경쟁, 성공 음성 중복 생성 방지, 403 권한 안내.
- 공식 요청 형식: https://github.com/neosapience/typecast-sdk (Python client.py, models/tts.py). 계정별 API 크레딧 및 권한은 Typecast에서 관리합니다.
