# v13.17.0 — Typecast 이상 활동 차단 대응

## 원인 분석

v13.16.3 검증에서 확인된 상황은 다음과 같습니다.

- 무료 API 플랜이고 크레딧 사용량은 0/15,000입니다.
- 캐릭터 목록은 불러와지지만, 첫 대사 합성부터 `403 UNUSUAL_ACTIVITY_DETECTED`로 막힙니다.
- 새로 발급한 키로 바꿔도 똑같이 차단됩니다.

이전 구조에서는 모든 합성 요청이 이 사이트의 `/api/typecast/voice` 서버 중계를 거쳤습니다.

- 이 서버는 Cloudflare Workers에서 돌고, Workers가 외부로 나갈 때 쓰는 IP는 수많은 서비스가 함께 쓰는 데이터센터 주소입니다.
- 무료 플랜의 이상 활동 감지는 보통 "같은 IP에서 여러 무료 계정 사용", "VPN·프록시·클라우드 주소"를 차단합니다.
  - 같은 코드를 쓰는 ElevenLabs가 이렇게 공개 설명합니다.
  - 유료 플랜에는 적용되지 않는다고 안내합니다.
- 목록 조회처럼 크레딧을 쓰지 않는 요청은 통과하고, 크레딧을 쓰는 합성만 막힌다는 점도 이 설명과 맞습니다.
- 공식 SDK는 항상 식별용 `User-Agent`를 보내는데, 이 서버의 요청에는 없었습니다.

Typecast가 이 오류의 판정 기준을 공개하지 않아서 원인을 확정하지는 못했습니다.

## 변경

1. **브라우저 직접 연결 (기본값 "자동")**
   - Typecast 합성 요청을 먼저 플레이어 기기의 인터넷 연결로 `https://api.typecast.ai/v1/text-to-speech`에 직접 보냅니다.
   - 요청 본문은 서버 경로와 한 글자도 다르지 않습니다(테스트로 확인).
   - 키는 이미 이 기기에만 보관되어 있고, 이제 이 사이트 서버를 거치지 않습니다.
2. **자동 대체**
   - Typecast가 브라우저 출처 요청(CORS 사전 요청)을 허용하지 않으면 합성 요청 자체가 전송되지 않아 크레딧이 들지 않습니다.
   - 이 경우 서버 중계로 한 번 대체하고, 이 탭에서는 이후 계속 서버 중계를 씁니다.
   - 시간 초과는 이미 처리·과금되었을 수 있으므로 다른 경로로 다시 보내지 않습니다.
3. **서버 중계 식별**: 중계 요청에 공식 SDK처럼 `User-Agent: dancheong-light-novel/13.17 (...)`를 보냅니다.
4. **차단 사유 구분**
   - 직접 연결에서도 `UNUSUAL_ACTIVITY_DETECTED`가 오면, 접속 주소가 아니라 계정 쪽 제한으로 안내합니다.
   - 서버 중계에서만 오면, 공용 클라우드 주소 때문일 수 있다고 안내합니다.
   - 두 경우 모두 추가 자동 합성은 중단하고, 저장된 음성은 계속 재생합니다.
5. **설정**: 음성·음악 → Typecast 연결 방식(자동 / 서버 중계만)을 추가했습니다.
6. **비용 기록**: 직접 연결한 호출도 사용량·비용 탭에 Typecast 크레딧 사용으로 기록합니다.

## 검증

- **자동 검사**
  - Node 테스트 507개가 모두 통과하고, tsc와 배포 빌드도 이상 없습니다.
  - 새 테스트 6개가 다음을 확인합니다.
    - 직접 요청의 형식, 그리고 서버 경로와 본문이 같은지
    - 사전 요청이 거부되면 한 번만 대체하고 그 선택을 기억하는지
    - 시간 초과 때 다시 보내지 않는지
    - 서버 중계만 설정 시 직접 요청을 건너뛰는지
    - 직접 연결 차단 시 계정 제한 안내와 코드가 나오고, 대사가 노출되지 않는지
    - 중계 `User-Agent`와 안내 문구
- **실제 Chromium**: 빌드된 셸에서 직접 요청 → 실패 → 서버 중계 → 탭 기억 순서가 실제 요청으로 확인되었습니다. 설정 선택지도 표시됩니다.
- **검증하지 못한 것**
  - 이 개발 환경은 `api.typecast.ai` 접근이 막혀 있습니다.
  - Typecast가 브라우저 출처 요청(CORS)을 허용하는지, 직접 연결로 무료 플랜 차단이 풀리는지는 실제 기기에서 확인해야 합니다.
