# v13.8 — 저장 실패 안내와 선택 요청 처리

## 확인된 문제

Cortex가 본문 저장 실패 후 입력을 차단하더라도 VN 선택지는 활성 상태였다. 원본의 `recoveryNotice`와 복구 버튼이 숨겨진 `.app` 안에 남았으며, `runTurnV1111()`의 조용한 반환을 VN이 성공으로 판단해 선택 화면을 닫았다.

## 변경

- 원본 `recoveryNotice` 노드를 VN 화면으로 옮긴다. 원본의 별도 저장·백업·복구 처리와 버튼 핸들러를 그대로 유지한다.
- 저장 공간 부족·저장 지연·복원 실패를 구분해 안내한다. 차단 상태에서는 새 본문 요청을 보내지 않는다.
- 선택 요청 뒤 새 턴 또는 같은 턴의 상태 변화가 없으면 실패로 알리고 입력을 보존한다.
- 저장 실패를 무시하고 설정 저장 성공으로 안내하지 않는다.
- 저장이 차단된 탭을 닫거나 새로고침할 때 브라우저의 이탈 확인을 요청한다.
- 기존 Cortex 저장 형식, 충돌 격리 정책, 작품 데이터와 이미지 캐시는 변경하지 않는다.

## 검증과 한계

- `vn-progress`, `vn-boot`, `vn-stage-timing`, `vn-streaming`: 37개 테스트 통과.
- 실제 VN 모듈과 모의 저장 실패를 사용하는 브라우저에서 안내·백업 핸들러·별도 저장 뒤 버튼 활성화·선택 뒤 다음 문장 표시를 확인했다.
- 실제 이용자의 저장 실패는 숨겨진 원본 안내에서 확인했다. 구체적인 저장소 오류 코드는 별도 진단이 필요하다. 이번 수정이 저장 공간 자체를 늘리거나 저장 실패를 무조건 해소하지는 않는다.
- 이미 열린 구버전 탭의 메모리를 새 배포로 덮어쓰지 않는다. 저장되지 않은 진행은 기존 탭에서 백업·별도 저장한 뒤 새 버전을 불러와야 한다.
