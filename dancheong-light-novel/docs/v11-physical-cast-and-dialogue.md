# v11 — 현장 인물과 대사 시점

## 잘못된 연결

단청 Cortex의 `imageCharacters`와 `createImageCapsule`는 이미지 모델에 제공할 **참조 후보**를 만든다. 원본 이미지 프롬프트가 본문의 의미를 해석해 인용·회상·실종 인물, 편지 작성자, 장소·물건의 소유자, 전화·사진 속 인물을 실제 현장 인물과 구분한다. v10의 VN 레이어는 참조 후보와 이전 이미지 명단을 그대로 스프라이트 명단으로 사용했다. 따라서 ‘한명진이 살던 집’ 같은 소유·회상 문맥도 인물을 화면에 올릴 수 있었다.

원본 비교 근거: 기존 단청의 `scene-references.test.mjs`, `scene-presence.test.mjs`, `image-identity-binding.test.mjs` 및 Cortex 이미지 요청 프롬프트. 이 프로젝트의 vendor 원본은 변경하지 않았다. SHA-256: `1e5fbc6ac09532852a3492b2821efd99d7b16961bff23cc52693d05bdfc77a43`.

## 변경

- 장면 v4는 공개 참조 후보를 `candidates`로 보관한다. 이 명단이나 오래된 캐시가 자동으로 화면 인물이 되지 않는다.
- 공개된 문단과 직전 공개 본문으로 문장별 현장 인물·화자를 결정한다. 선택한 본문 제공사의 모델을 사용한다. 사진, 비공개 인물 설정, 내부 인물 ID, 미공개 초고는 이 요청에 포함하지 않는다.
- 문장별 근거와 후보 핸들을 검증한다. 확인되지 않거나 요청이 실패하면 인물을 표시하지 않는다. 실패는 페이지 이동으로 재호출하지 않으며 명시적 재시도를 제공한다. 제공사 자동 전환은 없다.
- 턴의 마지막 장면을 모든 대사에 적용하지 않는다. 앞에서 말하고 뒤에서 떠나는 인물은 각 문장에 맞춰 나타나고 사라진다.
- 읽는 문단과 다음 공개 문단의 이미지를 미리 준비한다. `COMMITTED`를 기다리는 조건을 제거했다. 아직 작성 중인 마지막 문단은 닫히거나 공개 스트림이 끝날 때 연출을 확정한다.
- 서술은 기존처럼 첫 문장부터 표시한다. 대사는 실제 현장 화자의 이미지가 준비되고 브라우저에 표시된 뒤 시작한다. 최초 이미지가 늦거나 실패하면 해당 대사에서 기다리며, 사용자가 ‘이미지 없이 읽기’를 선택할 수 있다. 자동 읽기도 이 대기를 지킨다.
- 배경·중립 인물·표정 이미지와 문단별 인물 배치를 재사용한다. 비용 탭에 ‘인물 배치’를 별도로 집계한다. 새 문단 확인 요청의 사용량은 선택한 본문 모델의 과금 또는 Go 구독에 따른다.

## 검증 범위

- Node 테스트 128개 통과, TypeScript 검사 및 프로덕션 빌드 성공.
- 새 테스트: 캐시된 한명진이 있어도 제외된 인물의 이미지를 로드·생성·표시하지 않음, 문장별 등장/퇴장, 중복 요청 방지, 실패 시 자동 재호출 방지, 비공개 초고 제외, 대사 이미지 디코딩 대기.
- 실제 Cortex 공개 외모 해제 모듈을 사용한 브라우저 fixture 확인: 회상 속 한명진 0회 생성, 나디아 1회 생성, 이후 스트리밍 턴에서 재사용. 이미지 응답을 수동 지연시키자 대사가 대기했고 응답 도착 후 인물과 대사가 함께 표시됐다. `STREAMING` 상태에서도 인물 표시를 확인했다. 브라우저 오류 없음.
- 비용 탭에서 인물 배치 6회와 이미지 호출이 구분되는 것을 확인했다.
- 위 fixture의 모델 응답·이미지는 테스트용이다. 문장 의미 판정의 모든 모델 출력이나 사용자의 실제 Fate/Seoul 저장 장면을 재현한 결과는 아니다. 실제 판정 정확도는 선택한 모델의 출력에도 영향을 받는다.
- Muse는 별도 작업 사본에서 비용 분류와 해당 테스트만 작성했다. 주 개발자가 diff를 읽고 검사 후 반영했으며 이미지 용도 허용 목록을 추가로 좁혔다. 핵심 인물 판정·표시·저장·통합은 주 개발자가 직접 수정했다.
