# v13.16.2 — 눈·입 움직임 정렬 보완

## 원인과 수정

- 기존 피부색·얼굴 비율 추정값으로 만든 직사각형 마스크가 머리카락을 눈으로 오인할 수 있었습니다. 몸통 위주의 정렬 검사는 머리 쪽 변형을 놓쳤습니다.
- 선택한 입상 자체에서 MediaPipe 얼굴 윤곽을 기기 안의 Worker로 측정합니다. 좌우 눈과 입술을 별도의 회전 마스크로 만들며, 검출 실패·여러 얼굴·비정상 기하·불투명도/대비 부족 시 이미지 요청 없이 정지 입상을 사용합니다.
- 모델 입력은 원본 비율을 유지한 768×1024 캔버스입니다. 편집 결과를 원본 좌표로 되돌리고 눈·입 밖의 RGB와 전체 알파는 원본에서 유지합니다. 얼굴 주변의 변형을 몸통과 별도로 검사합니다.
- 기존 유료 프레임도 표시 전에 재검사합니다. 키를 바꾸거나 일괄 삭제하지 않으므로 업데이트 때문에 자동으로 다시 구매하지 않습니다. 거부된 프레임은 자동 재생성하지 않습니다.
- 표정 이미지와 움직임 프레임의 원본을 일치시켜, 늦게 도착한 이전 표정의 프레임이 새 입상에 적용되지 않게 했습니다. 최초 교체 전에 이미지를 디코딩합니다.
- 눈 감김과 입 벌림이 겹치면 통과한 두 부분을 합칩니다. 추가 이미지 호출은 없습니다. 음성이 없을 때의 입 움직임은 대사 출력 중에만 적용합니다.
- 옵션은 기존처럼 기본 OFF, OpenAI 마스크 편집만 지원합니다. Gemini에 마스크를 지원하는 척 보내지 않습니다.

## 성능·비용

- 얼굴 검출은 텍스트 표시를 막지 않는 비동기 Worker입니다. 첫 사용 시 자체 호스팅 모델/런타임 약 16MB를 불러오며, 이후 브라우저 HTTP 캐시를 사용할 수 있습니다. 얼굴 검출 API 비용은 없습니다.
- CPU 측정은 입상당 최대 네 개의 제한된 크롭/회전 시도로 끝납니다. 준비된 프레임 캐시는 네 묶음, 좌표 캐시는 16개이며 유휴 Worker는 90초 뒤 종료됩니다.
- 실제 눈·입 편집 이미지를 새로 요청하면 기존 이미지 요금이 발생합니다. 검출 불확실·이미 거부된 프레임에 대한 반복 유료 요청은 하지 않습니다.

## 검증과 한계

- Node 전체 자동 테스트 490개 통과, TypeScript 검사 통과.
- Chrome에서 실제 히시리·아처·홍재 입상 세 장의 눈/입 마스크를 확대해 확인했습니다. 해당 나디아 입상은 윤곽 검출에 실패하여 정지 원본을 유지하는 것을 확인했습니다. 모든 애니메이션 그림을 검출한다고 보장하지 않습니다.
- 로컬 합성 픽셀 fixture로 실제 편집 준비 → 결과 검증 → 표시 프레임 생성 경로를 확인했습니다. 머리 변형 거부, 눈 외부 픽셀·알파 보존, 양쪽 눈 변화, 원본/표정 불일치, 눈·입 동시 선택을 검사했습니다.
- 이번 검증에서 새 유료 편집 이미지를 호출하지 않았습니다. 따라서 모든 모델 출력의 미적 품질이나 자연스러운 연기까지 검증했다는 의미는 아닙니다. 실제 결과가 정렬 검사를 통과하지 못하면 정지 입상을 유지합니다. 실제 iOS Safari 기기 검증은 하지 않았습니다.
- Muse는 독립된 순수 프레임 선택 함수와 테스트만 작성했습니다. 주 개발자가 전체 결과를 읽고 원본 일치 검사와 실행 경로를 통합했으며, 테스트 및 실제 Chrome 렌더링을 확인했습니다.

브라우저 저장 데이터와 Cortex 엔진 원본은 변경하지 않습니다.
