# v13.11.1 — 연출·읽기 성능 점검

검토일: 2026-09-26. 비교 대상은 배포된 v13.11.0(6d766477)과 이번 수정본이다.

## 판단

월희 리메이크에서 참고한 컷 전환, 인물 강조, 사건 배경, 구도, 효과음과 읽기 조작의 구조는 갖추고 있다. 그러나 작가·원화가·성우가 장면별로 완성한 상용 게임과 동일한 품질이라고 판단하지 않는다. 자동 생성 이미지의 얼굴·포즈·연출 판단 오차, 음성 연기, 외부 API의 최초 응답 시간은 여전히 차이가 크다. 이번에는 이미지 해상도를 낮추거나 비싼 모델로 바꾸는 대신, 읽기 중 불필요한 정지와 중복 계산을 고쳤다.

## 확인·수정

| 구간 | 발견한 문제 | 수정 |
|---|---|---|
| 긴 기록 + 스트리밍 | 문장이 추가될 때 과거 확정 턴까지 전부 다시 분할 | 공개 본문·상태·화자 주석이 바뀐 턴만 재분할. 동일 길이의 수정·주석 무효화·되감기도 반영 |
| 인물 판정 | 화면 조회마다 이미 검증한 문단의 전체 인물 타임라인을 재검증 | 판정과 공개 근거가 같을 때만 결과 재사용. 근거/후보/복장이 바뀌면 재검증 |
| 미리 준비 | 화면이 그대로여도 300ms마다 모든 준비 문단을 다시 구성 | 페이지·읽기 위치·설정·취소 상태가 바뀔 때만 준비 목록 갱신 |
| 인물 표시 준비 | 먼저 끝난 인물도 느린 배경/다른 이미지가 끝나야 미리 디코딩 | 각 입상이 저장소에서 발견되거나 생성되는 즉시 별도로 준비 |
| 이미지 연산 | 투명 영역·얼굴 측정·PNG 인코딩이 본문과 같은 스레드에서 실행 | 원래 해상도와 알고리즘을 그대로 별도 Worker에서 처리. 미지원/실패 시 기존 경로로 복귀 |
| 화면 갱신 | 여러 이미지 알림마다 연속으로 전체 UI 갱신 | 알림을 한 프레임으로 묶음. 사용자의 다음/이전 입력은 즉시 처리 |
| 장 제목 | 턴 전환 때 1.4초 동안 본문 숨김/정지 | 오른쪽 위의 작은 제목으로 표시, 본문 계속 재생 |
| 늦은 강조 연출 | 인물 판단이 늦으면 읽던 본문을 검은 화면이 덮음 | 해당 페이지 읽기 시작 시 준비된 강조만 전체 화면으로 재생 |
| 기타 | 준비 알림마다 동기 저장, 큰 이미지 문자열을 DOM 속성에 복제, 불필요한 과거 배경 전체 조회 | 읽기 위치 변경 시에만 저장, 이미지 키를 객체 속성으로 유지, 필요한 경우만 최근 배경부터 조회 |
| 숨긴 탭 | 뒤에서 화면 갱신과 새 문단 준비를 계속 수행 | 화면 갱신과 새 준비를 멈추고 복귀 시 현재 상태 반영. 이미 시작된 유료 요청은 결과를 보존 |

## 유지한 기준

- 인물 때문에 본문을 기다리는 유예는 턴당 최대 **5초**, 다음 대사마다 다시 기다리지 않는다.
- 미공개 초안은 표시하거나 인물 판단에 사용하지 않는다. 인용·기억·전화 속 인물은 현장 인물로 바꾸지 않는다.
- 같은 인물/복장/표정 및 장소의 유료 이미지 캐시 키를 변경하지 않았다. 업데이트만으로 기존 그림을 재생성하지 않는다.
- 이미지 API 동시 요청 제한 2, 문단 미리 생성 범위 2, 사건/추가 구도/눈·입 마스크/음성의 선택 설정은 유지한다.
- 주요 사건은 배경으로 표현하고, 그 배경에 그려진 참여자의 입상만 숨긴다. 등장 외형이 확립되지 않은 인물은 사건 이미지에 넣지 않는다.
- 공개 설정의 신장·인물별 크기 보정, 모바일 가로/세로 배치, 터치 입력 16px 이상, 핀치 줌, 저장 슬롯을 유지한다.

## 검증 결과

### 로컬 계산 비교

같은 PC, Node v24.19.0. 100턴(과거 본문 151,470자)을 두고 마지막 턴에 공개 문장을 덧붙였다. 80회 측정 중앙값이다. 모델 응답/통신 시간은 포함하지 않는다.

| 작업 | v13.11.0 | v13.11.1 |
|---|---:|---:|
| 스트리밍 중 페이지 목록 계산 | 2.968ms | 0.224ms |
| 20비트 문단의 인물 조회 1회 | 0.029ms | 0.003ms |

인물 조회는 100회씩 100묶음을 측정한 묶음별 평균의 중앙값이다. 브라우저 전체 프레임 속도가 이 비율로 빨라진다는 뜻은 아니다.

### 브라우저·실제 그림 검사

기존 나디아·홍재·오요한 입상 3장으로 원래 경로와 Worker 경로를 비교했다. **결과 크기가 같고 모든 픽셀 채널의 최대 차이가 0**이었다. Worker의 실제 실행도 확인했다.

| 샘플 | 처리 완료 시간(전 → 후) | 가장 긴 requestAnimationFrame 간격(전 → 후) |
|---|---:|---:|
| 저장된 입상 3장 | 121 → 164ms | 18 → 18ms |
| 높이 2,048px로 만든 입상 3장(부하 검사) | 365 → 369ms | 106 → 18ms |

단일 로컬 Chromium 실행 결과다. 이미지 처리 자체를 더 빨리 끝내는 것보다 본문/조작 스레드의 정지를 줄이려는 변경이다. 고성능 PC에서 나온 수치이며 모든 모바일 기기의 FPS를 보증하지 않는다. 2K 샘플은 부하 검사용 확대 복사본이지 새로 생성한 그림이 아니다.

- 실제 앱 모듈을 쓰는 격리된 모의 장면에서 인물 판정 지연 시 **5,021ms**에 본문 대기 해제를 확인했다.
- 데스크톱, 390×844 세로, 844×390 가로에서 본문·두 입상·읽기 도구·장 제목·컷인을 직접 확인했다.
- 가로 모바일 입력창의 실제 계산된 글자 크기 16px를 확인했다. 실제 iPhone 키보드와 Safari 포커스 확대는 이번에 실기기 검증하지 않았다.
- 자동 검사 **302개 통과**, TypeScript 검사 통과. 캐시 무효화·초안 비노출·배경보다 먼저 완성된 인물 준비·늦은 강조·Worker 오류 복귀를 포함한다.
- 이번 검증은 모의 API와 이미 저장된 그림을 사용했다. 유료 이미지/음성/집필 호출을 새로 실행하지 않았으며, 실제 제공자 지연·요금·연기 품질의 비교 시험은 아니다.
- Muse는 별도 복사본의 CSS 목록 조사만 수행했다. 제품 변경과 결과 판단은 주 개발자가 직접 수행했다.

## 남은 차이

1. 처음 만드는 인물·사건 그림의 생성 시간은 외부 모델의 영향을 받는다. 본문 우선 표시와 캐시/미리 준비로 완화하지만 기다림을 완전히 없애지는 못한다.
2. 그림과 TTS는 장면별 원화·성우 디렉팅을 대신하지 못한다. 정교한 동작, 인물 간 접촉, 자연스러운 입 모양과 감정 연기는 계속 검수해야 한다.
3. 얼굴 측정은 픽셀 휴리스틱이다. 특수 화풍·모자·측면 구도에서는 기본 프레이밍으로 복귀할 수 있다. 이번 변경은 그 판단 알고리즘이나 외형을 바꾸지 않는다.
4. 많은 기종의 GPU/메모리, 실제 Safari 키보드, 긴 실전 세션의 발열/배터리 검사는 추가 실기기 검증 영역이다.
