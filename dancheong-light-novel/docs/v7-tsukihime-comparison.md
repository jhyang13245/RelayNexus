# 단청 라이트노벨 v7 — 월희 리메이크 연출 비교와 구현

분석일: 2026-09-24. 비교 기준: 공개사이트 v6 → 이번 v7.

## 1. 무엇을 비교했는가

- 사용자가 지정한 [월희 리메이크 플레이 영상](https://www.youtube.com/watch?v=4atB7vy5erY&list=PLgYUax1vtTlfSLR49qhxPO4r9IGlToj2U&index=5): 「월희 리메이크 ─ 4. 화염혈하 1 (1/2)」, 月記 ㅡMoon recordㅡ.
- 약 05:58, 17:54, 29:50, 41:46, 53:34~53:42의 화면을 직접 확인했다. 전체 약 59분 영상을 연속 시청하거나 프레임별 전환 시간을 측정한 분석은 아니다.
- [공식 영문 사이트](https://tsukihime-en.com/)와 [TYPE-MOON 공식 소개](https://typemoon.com/products/tsukihime/)에서 작품의 시각·음악·음성 제작 구성을 참고했다.
- 단청은 기존 공개사이트 v6 코드와 실제 로컬 실행 화면을 비교했다. v7 화면과 입력 흐름은 데스크톱·모바일 브라우저에서 검증했다.

영상의 하단 일본어 자막은 영상에 덧붙은 표시일 수 있어 게임의 필수 UI로 취급하지 않았다. 아래 해석 중 ‘회상처럼 보이는’ 표현은 화면의 색과 구도에서 한 추론이다.

## 2. 가장 큰 차이

월희의 인상은 **문장, 인물의 크기·위치, 장면의 색, 침묵과 전환이 같은 박자로 움직이는 것**에서 나온다. 단청 v6는 배경과 표정의 재사용 기반은 갖췄지만, 문장이 바뀔 때마다 표시 위치가 달라지고 새 턴의 끝으로 이동하는 읽기 흐름 때문에 그 박자가 끊겼다.

이번 v7에서는 먼저 매 문장을 읽는 경험과 반복적으로 나타나는 화면 연출을 수정했다. 사건마다 직접 그린 CG, 성우 연기, 곡별 음악 연출은 별도의 제작 자산과 연출 데이터가 필요하다.

## 3. 관찰한 차이와 v7 반영

| 항목 | 참고 영상에서 확인한 특징 | 단청 v6의 차이 | v7 구현 |
|---|---|---|---|
| 본문 배치 | 서술과 따옴표 대사가 화면 상단의 같은 읽기 영역에 표시됨 | 서술은 상단, 대사는 하단 창으로 이동 | NVL을 기본값으로 통일. ADV 하단 창은 설정에서 선택 |
| 문장 축적 | 앞 문장이 남고 새 문장이 이어짐 | 한 조각의 문장을 교체하는 구조 | 턴 안에서 읽은 문장을 누적하고 분량에 따라 다음 묶음으로 넘김 |
| 글의 강조 | 앞 문장이 조금 어둡고 현재 문장은 밝음 | 이전 문장과 현재 문장의 시각적 관계가 약함 | 이전 문장 밝기를 낮추고 현재 문장은 흰색으로 표시 |
| 글의 리듬 | 화면을 읽는 시간과 장면의 정지가 강조됨 | 균일한 타자 효과, 스트리밍 표시와 페이지 진행이 겹침 | 문장부호별 멈춤. 첫 클릭은 표시 중인 문장 완성, 다음 클릭이 진행 |
| 새 턴 진입 | 영상 속 이미 작성된 이야기는 문장 순서대로 전개됨 | 새 턴 감지 시 마지막 페이지로 이동하는 코드가 있었음 | 생성 중 현재 페이지 유지 → 확정된 새 턴의 첫 페이지부터 읽기 |
| UI 존재감 | 화면 대부분을 그림과 글에 할당 | 장면 정보와 관리용 상태가 상시 노출 | 읽기 제어를 화면 가장자리로 정리. 정상 이미지 상태 문구 제거 |
| 인물 구도 | 약 17:54의 얼굴 클로즈업, 29:50의 서 있는 인물 구도가 다름 | 주로 일정한 크기의 인물 배치 | 서술의 명시적 근접·원경 표현에 따라 구도 전환. 뒤따르는 대사에도 유지 |
| 색과 분위기 | 약 41:46의 세피아·어두운 가장자리, 53분대의 붉고 어두운 화면 | 기본 배경 전환 중심 | 명시적 기억·회상 서술에 세피아와 비네트. 임의로 모든 감정에 필터를 걸지는 않음 |
| 장면 전환 | 장소·구도·분위기에 따라 다른 화면 구성 | 이미지 URL 변경에 일괄적인 암전 | 같은 환경 이미지는 크로스페이드. 장소 이동·시간 변화는 별도 짧은 암전 |
| 충격 연출 | 긴장 장면에서 평상시와 다른 시각적 분위기 | 문장 사건과 화면 효과의 연결이 약함 | 폭발·충돌·문이 쾅 닫힘 등 명시적 서술에 짧은 화면 흔들림. 본문은 고정 |
| 인물 교체 | 장면 위에 인물이 배치되고 구도에 따라 강조됨 | 표정 교체 기반은 있으나 퇴장 처리가 즉시 이루어짐 | 기존 표정 교차 표시 유지, 퇴장 페이드 추가 |
| 선택의 순간 | 장면의 일부처럼 다음 행동을 고르는 경험이 중요 | 추천이 없으면 입력 폼이 바로 열림 | 중앙 선택 화면과 직접 입력을 구분. 추천이 없을 때도 본문으로 복귀·장면 이어가기 가능 |
| 재독 | 긴 이야기를 읽는 게임에 필요한 기능 | 문장별 읽기 위치와 재독 범위 관리 부족 | 자동 읽기, 읽은 부분만 건너뛰기, 미독 본문을 숨기는 기록, 읽기 위치 복원 |
| 조작 | 게임 전체를 반복 조작하는 편의성이 필요 | 다음/이전 중심 | 화면 클릭, 키보드 단축키, 글 숨기기, 전체 화면, 읽기·연출 설정 |

자동 읽기·키보드·기록의 개별 동작은 이번 영상의 메뉴에서 모두 실측한 기능이라고 주장하지 않는다. 긴 비주얼노벨 플레이에 필요한 조작 기능으로 이번 구현에 포함했다.

## 4. 읽기 흐름의 구체적인 동작

1. 기존 Cortex가 확정한 본문을 읽기 페이지로 나눈다. 집필 내용과 정사 판정은 원본 엔진이 맡는다.
2. 같은 턴의 문장은 읽은 지점까지만 누적한다. 화면 너비와 글자 크기를 고려해 묶음을 나누며, 매우 긴 문장은 영역 안에서 스크롤할 수 있다.
3. 자동 읽기는 문장 표시가 끝난 후 분량에 맞게 기다린다. 선택·입력·다음 턴 생성은 자동 실행하지 않는다.
4. ‘읽은 부분’은 이미 표시를 마친 마지막 문장까지만 이동한다. 다음 미독 문장을 자동으로 읽은 것으로 처리하지 않는다.
5. 설정·기록·메뉴·본문 숨김·백그라운드 탭에서는 진행이 멈춘다. 자동 모드는 설정이나 탭 전환 후 임의로 재개하지 않는다.
6. 생성 중에는 읽던 장면을 유지하고 대기 표시를 보여준다. 확정되면 새 턴의 첫 문장으로 이동한다.
7. 작품별 턴 ID와 본문 오프셋으로 읽는 위치를 이 브라우저에 저장한다. 과거 기록을 읽는 것은 정사를 되돌리거나 다른 분기를 만드는 동작이 아니다.

단축키: Space/Enter/→ 다음, ← 이전, A 자동, S 읽은 부분, L 기록, H 본문 숨김, F 전체 화면. 입력창과 설정을 조작할 때는 단축키가 본문을 진행시키지 않는다.

## 5. 이미지 재사용과 모델

배경·기본 인물·표정을 분리한 v6 구조를 유지했다. 같은 장소·조명·환경은 배경을 재사용하고, 표정이 달라지는 문장에서는 필요한 표정만 준비한다. 이미 만든 같은 표정은 다시 사용한다. 과거 문장으로 이동해도 그 시점의 장면을 사용한다.

OpenAI 이미지와 Nano Banana 2의 선택·키 입력, 본문 모델 설정, 사용량·비용 탭도 유지한다. **이번에 추가한 화면 구도·필터·자동 읽기는 별도 모델 호출을 만들지 않는다.** 미리 없던 이미지가 필요한 문장에 도달하면 기존 이미지 생성 경로의 요금이 발생할 수 있다.

표정 참조 이미지를 보내는 것은 인물 일관성을 높이는 수단이다. 생성 모델이 얼굴·의상·선화를 항상 동일하게 재현한다는 보장은 없다. 이번 검사는 모델을 실제로 유료 호출한 화질 평가가 아니다.

## 6. 아직 월희와 차이가 큰 부분

| 남은 차이 | 현재 한계 | 다음 단계에서 필요한 것 |
|---|---|---|
| 사건 전용 CG | 배경+인물 레이어와 확대는 두 인물이 접촉하는 행동, 복잡한 액션 구도를 완성하지 못함 | 주요 사건별 CG 생성 기준, 인물 참조, 장면 검수와 재사용 |
| 구도 다양성 | 현재의 클로즈업은 기존 인물 그림의 확대. 측면·뒷모습·손·눈 전용 컷이 아님 | 포즈·각도별 인물 자산과 컷 정의 |
| 연출의 의도 | 보수적인 서술 규칙은 작가가 장면마다 지정한 연출보다 단순하며 오탐·누락 가능 | 명시적인 장면 큐: 대상 인물, 구도, 전환, 지속 시간, 색, 음향 |
| 다인 장면 | 화자 강조와 기존 배치는 있으나 모든 문맥에서 인물 간 공간 관계를 해석하지 못함 | 인물별 무대 위치와 시선·동선 데이터 |
| 음성·음악 | 선택 가능한 조작 효과음만 있음. 성우 음성·BGM·환경음은 추가하지 않음 | 사용 가능한 음원, 목소리, 대사 동기화와 믹싱 |
| 장면별 타이밍 | 글자·문장부호·분량 기반의 자동 시간 | 작가가 지정한 침묵, 음악의 시작·끝, 컷별 속도 |
| 저장·분기 관리 | 현재 브라우저의 진행 저장과 읽기 위치 복원 | 여러 저장 슬롯, 분기 시점 관리, 세이브 미리보기 |
| 생성 대기 | 월희처럼 모든 자산이 미리 준비된 게임과 달리 본문·이미지 대기 발생 | 비용 한도를 둔 사전 준비, 자산 검수, 재사용률 개선 |

따라서 v7의 성과는 ‘NVL 읽기와 기본 장면 연출이 연결된 플레이어’다. 월희 수준의 CG·성우·음악·장면별 수작업 연출을 모두 완성한 상태는 아니다. TYPE-MOON의 그림·로고·음원은 이 제품 자산으로 가져오지 않았다.

## 7. 검증

- `npm test`: 총 69개 통과. 기존 이미지 재사용·제공사 요청·비용 검사와 새 읽기/연출 검사를 포함한다.
- `npx tsc --noEmit`, `node --check public/vn.js`, `npm run build` 통과. 빌드에서 Cortex 원본 SHA-256 검증도 통과했다.
- 긴 대사를 분리해도 원문·화자·본문 오프셋 보존, 미래 문장 미노출, 새 턴 첫 페이지, 읽은 범위 건너뛰기, 문장부호 지연, 대사 속 표현으로 연출 오작동 방지, 기록 이동 시 구도 재구성.
- 로컬 브라우저: 실제 단청 작품의 첫 화면, 1280×720 / 390×844 렌더링, NVL 누적·대사, ADV 옵션, 글 숨김, 설정, 새로고침 후 위치 복원.
- 유료 호출 없는 격리 fixture: 1.6초 생성 대기 중 기존 문장 유지, 3/3에서 새 턴의 4/7로 이동, 자동 모드가 선택 화면에서 정지, 미독 5/7 앞의 4/7에서 스킵 정지, 기록에 읽은 4개 항목만 표시.
- 동일 교실 표정 변경에서 배경 0회 / 기본 인물 0회 / 표정 1회 추가 요청을 확인했다. 이는 이미 저장된 배경·인물을 재사용한 fixture의 호출 횟수다.
- 장소가 밤의 복도로 바뀐 다음 턴에서는 배경 요청이 1회 추가됐고, 회상 필터와 첫 문장 진입을 확인했다. 확인한 브라우저 콘솔에는 오류·경고가 없었다.
- 실 API 키를 사용한 유료 본문/이미지 생성, 성우·음악 품질, 전체 장편 플레이는 이번 검증 범위에 포함하지 않았다.

## 8. 구현 위치

- `public/vn-reader.mjs`: 누적 본문, 읽기 위치, 자동/재독 진행.
- `public/vn-direction.mjs`: 현재까지 읽은 서술 기반의 구도·회상·충격 효과, 선택적 조작음.
- `public/vn-reader.css`: NVL/ADV 화면, 선택·기록·빠른 조작, 모바일·움직임 최소화.
- `public/vn.js`: 원본 엔진과 읽기 플레이어의 통합.
- `public/vn-core.mjs`: 긴 대사 분할과 화자/원문 오프셋 보존.
- `tests/vn-reader.test.mjs`, `tests/vn-core.test.mjs`: 주요 회귀 검사.

너름 작품 목록, 지음 편집기 연결, Cortex 원본 파일의 해시 검증을 유지한다.
