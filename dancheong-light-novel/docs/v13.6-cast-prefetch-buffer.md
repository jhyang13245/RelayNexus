# v13.6 — 화자 신원 확인, 선행 이미지 준비, 문장 대기 표시

## 수정

- 인물 판정에 이름·별칭뿐 아니라 공개 프로필·역할·나이·성별을 전달합니다. 숨겨진 설정, 이미지 경로, 내부 인물 ID는 모델 입력에 넣지 않습니다.
- 현장 등장 근거와 해당 인물임을 확인하는 이름/별칭 근거를 별도로 확인합니다. 등록되지 않은 교수를 실종된 외할머니 등 기존 인물에 억지로 연결하지 않습니다. 본문에서 확인되는 일반 호칭은 `교수`처럼 표시할 수 있습니다. 신원이 확인되지 않는 인물은 다른 사람의 초상으로 대체하지 않습니다.
- 화면의 화자 이름은 확인된 인물 판정으로 결정합니다. 기존 집필 주석에 잘못 연결된 이름이 우선 표시되던 문제를 수정했습니다.
- V4 이하 인물 판정은 다시 확인합니다. 기존 배경·인물 이미지와 저장 진행은 삭제하지 않습니다. 다시 확인하는 문단에는 본문 모델 호출 비용이 발생할 수 있습니다.
- 현재·다음 문단만 준비하던 범위를 현재 턴 및 새로 도착한 턴의 공개 본문 전체로 확대했습니다. 완결된 공개 문단부터 최대 3개 인물 판정을 동시에 처리하며, 실제 표시는 해당 등장 시점에 맞춥니다. 이미지 생성 완료를 기다리는 동안에도 이후 문단의 인물 판정과 준비를 계속하며, 이미지 디코딩도 앞서 준비합니다.
- 아직 공개되지 않은 집필 초안은 읽지 않습니다. 따라서 아직 생성되지 않은 인물 정보를 미리 알거나 모든 대기를 없애는 기능은 아닙니다. 같은 이미지 요청은 공유하고, 작품 전환으로 취소된 대기 작업은 실행하지 않습니다.
- 현재 문장이 모두 표시된 뒤 다음 문장/대사 이미지가 준비되지 않았다면 문장 바로 옆에 점 3개 대기 표시를 보여 줍니다. 준비 완료 시 사라지며, 동작 줄이기 설정에서는 정지된 점으로 표시합니다.

## 검증

- 인물 판정, 기존 이미지 재사용, Cortex 공개 정보 투영, 스트리밍, 읽기 위치, 연출 관련 회귀 테스트 118개 통과. 느린 배경이 뒤쪽 인물 준비를 막지 않는 경우를 포함합니다.
- 로컬 실제 VN 화면과 모의 모델 응답으로 교수 이름 표시, 한명진 초상 요청 0회, 첫 문장(1/9)에서 뒤쪽 나디아 초상 요청 시작, 등장 전 숨김, 등장 및 대사와 초상 동시 표시를 확인했습니다.
- 실제 브라우저 렌더링에서 문장 대기 표시 출현·해제를 확인했습니다. Muse가 별도 작업 복사본에서 작성한 대기 표시 CSS는 원본 보존 여부와 차이를 직접 검토하고 화면 확인 후 통합했습니다.
- 이번 검증은 비용을 발생시키는 실제 이미지 API 호출이나 사용자의 저장 플레이 재진행 없이 수행했습니다. 임의의 모든 모델 응답에서 화자 의미 해석이 완벽함을 보장하는 테스트는 아닙니다.
