# v13.9.1 — 판정 보완 재시도 버튼 연결

## 원인

Cortex는 `ADJUDICATION_PENDING` 복원 지점이 있으면 기존 입력창의 `#send` 버튼을 "판정 보완 다시 시도"로 바꾼다. v13.8에서 안내문 `#recoveryNotice`를 라노벨 화면으로 옮겼지만, 숨겨진 기존 입력창에 있는 이 버튼은 연결하지 않았다. 라노벨의 일반 진행 버튼도 보류된 판정을 `busy()`로 차단하므로 안내만 보이고 재시도할 수 없었다.

## 수정

- 진행 안내 아래 전용 **판정 보완 다시 시도** 버튼을 표시한다.
- `CORTEX_SAME_TURN_RESUME_V1` 복원 지점이 있는 비트에만 표시한다. 기존 Cortex의 실제 요청 잠금 및 저장 실패 잠금을 따른다.
- 입력을 설정하거나 새 턴을 만들지 않고 원본 `runTurnV1111()`의 동일 비트 복구 경로를 호출한다. 원본 엔진·판정 프롬프트·저장 형식은 변경하지 않았다.
- 처리 중에는 **판정 보완 중…**으로 표시하고 중복 실행을 막는다. 다시 실패하면 재시도 가능 상태로 돌아오며, 성공하면 버튼과 안내를 닫는다.
- 엔진 안내가 다시 그려져도 버튼이 지워지지 않도록 안내 본문의 형제 요소로 배치했다.

## 검증

- 전체 Node 테스트 209개, 타입 검사, 배포 빌드 통과.
- 추가 테스트: 같은 비트 확정·본문과 입력 보존, 복원 지점 없는 호출 차단, 엔진/저장 잠금, 동시 클릭, 재실패 후 재시도, 판정 도중 저장 실패.
- 로컬 브라우저의 합성 판정 응답으로 버튼 표시 → 요청 중 비활성 → 실패 후 재활성 → 재시도 성공 → 안내 종료를 확인했다. 두 번의 요청 동안 턴 수는 1개, 공개 본문과 읽는 위치는 유지됐다.
- 실제 유료 API와 사용자의 현재 세션은 호출하거나 변경하지 않았다. 버튼 복구는 판정 요청 자체의 실패 원인을 해결했다는 의미는 아니다.

## 단청 v1.23.1과의 비교

공식 단청의 배포 커밋 `eab4833a66a948d68098d7c3ee544e1336cbadad`와 로컬 소스가 일치함을 Sites에서 확인했다. `1.23.1`은 단청 사이트 버전이며 두 사이트 모두 내부 Cortex v1.42.0을 기반으로 한다. 원본 HTML 차이는 7개 줄로, GPT 6 Luna 기본 집필 모델, 표시 속도 적용, 비용 계산, 모델 라우팅과 추론 설정에 관한 변경이다. 본문 생성·같은 비트 판정 복구·저장 알고리즘은 동일 기반이다.

라노벨은 아직 GPT 5.6 Luna 집필 설정을 사용하며, 별도의 인물 판정·이미지 선행 생성·표정·연출·읽기 UI를 가진다. 따라서 공식 단청 최신 사이트 전체의 기능과 완전히 동일한 구현은 아니다. 이 수정에서는 모델 설정을 바꾸지 않았다.
