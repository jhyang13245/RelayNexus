# v13 — 연출·무대·캐릭터 디자인 개선 (v13.1 검토 반영 포함)

이 문서는 v13·v13.1 당시의 기록이다. 얼굴 합성은 v13.2에서 제거했으며 현재 동작은 [v13.2 변경 내용](v13.2-expression-redraw.md)을 따른다.

2026-09-25. v12 코드 리뷰에서 지적한 "비주얼노벨답지 않은 시각 요소"를 수정한 버전이다.

## 1. 연출 판단: 정규식 → 기존 인물 배치 호출에 연출 필드 추가

v12의 표정·구도·충격 연출은 서술 속 키워드 정규식에만 의존했다. 대사의 감정은 표정에 반영되지 않았고, 구도 변화와 충격 연출은 거의 일어나지 않았다.

- 문단마다 이미 보내던 인물 배치 요청(`vn-cast.mjs`)의 JSON 스키마에 `expressions`, `focus`, `shot`, `transition`, `fx`, `mood`, `cg`를 추가했다. **새 모델 호출은 없다.** 출력 토큰 상한만 4096 → 6144로 늘렸다.
- 모든 값은 닫힌 목록(enum)이다. 무대에 없는 인물의 핸들이나 목록 밖의 값은 무시하고 `medium/none/normal`로 떨어진다. 연출 값이 잘못돼도 검증된 인물 배치는 유지된다.
- 기존에 저장된 V2 인물 배치 결정은 캐시 키가 그대로라 **다시 과금되지 않는다.** V2 결정, 스트리밍 중인 문단, 요청 실패 때는 v12의 정규식 연출이 그대로 동작한다.
- 표정은 모델이 준 값이 서술 정규식보다 우선한다(`emotionsFor`).

## 2. 무대(인물 레이어)

| 문제 | 수정 |
|---|---|
| 인물 퇴장 시 남은 인물이 순간이동 (`right`/`width`가 transition 대상이 아님) | 등장 순서를 유지하는 `stageOrder`, 인원수별 고정 위치 `stagePositions`. `left`·`width`·`height` 모두 transition. 등장은 서 있을 쪽에서 미끄러져 들어옴 |
| 화자 강조가 `brightness(.85)` 하나 | 화자 앞으로(z-index), 1.02배, 말하기 시작할 때 짧게 튀는 동작. 비화자는 `brightness(.66) saturate(.8)` |
| 인물마다 크기·머리 위치가 제각각 | 알파 경계 상자로 머리 위치를 찾아 **머리 위 3%, 머리 가로 중앙, 잘린 아랫단은 화면 끝에 붙도록** 정규화(`vn-sprite.mjs`). 기존 캐시 이미지에도 표시 시점에 적용되어 재생성이 필요 없다 |
| 키 차이가 사라짐 | 공개 프로필에 `키 158cm`처럼 명시된 경우만 0.88~1.05배 |
| 밤 배경 위에 한낮 조명의 입상 | 시간대별 색 보정(`data-light` = night/dusk/dawn) |
| 이미지 대기 중 빈 무대 | 생성 중인 인물 자리에 흐린 실루엣과 이름표 |
| 모바일 NVL에서 인물이 본문을 가림 | 모바일 NVL 서술 중 인물 45%, 대사 중 62% 불투명도 + 본문 뒤 전체 어둠막 |

## 3. 표정 교체 때 몸이 튀는 문제

이미지 편집 모델은 "표정만 바꿔라"를 요청해도 몸·머리카락·윤곽선을 조금씩 다시 그린다. v13은 편집 결과에서 **얼굴 영역(타원, 가장자리 35% 페더)만 잘라 중립 입상에 합성**한다(`compositeFace`).

- 편집 결과가 이동했으면 머리 위치 기준으로 맞춘 뒤 합성한다.
- 인물 크기가 6% 넘게 달라졌거나 크게 이동한 경우에는 합성하지 않고 v12처럼 편집 결과 전체를 쓴다.
- 얼굴 위치는 "머리~허벅지 입상에서 머리는 전체 높이의 약 21%"라는 가정으로 추정한다. 특이한 구도(고개를 크게 숙임 등)에서 어색하면 설정 → 표정 교체 → "생성된 전체 이미지"로 되돌릴 수 있다.

## 4. 캐릭터 디자인(생성 프롬프트)

- **작품 공통 그림체 지침(`ART_DIRECTION`)**을 배경·입상·사건 CG 프롬프트 앞에 붙인다. 표정 편집 프롬프트에는 붙이지 않는다(그림 전체를 다시 그리게 만들 수 있어서).
- 기본 지침은 기존 캐시 키를 바꾸지 않는다. 설정의 "이 작품의 그림체 지침"을 입력하면 그 작품의 배경·인물 키가 바뀌어 새 그림체로 다시 생성된다(비용 발생, 설정 화면에 안내).
- 입상 프롬프트: "simple standing pose"를 빼고 성격이 드러나는 자세·몸짓, 알아보기 쉬운 실루엣, 대표 색 하나를 요구한다. 머리 위 여백과 허벅지 중간 잘림 위치를 명시한다.

## 5. 화면 효과

- 전환: `fade`(암전), `wipe`(가로 와이프, 시간 경과), `blur`(흐림 → 초점, 깨어남·회상 진입), `flash`(흰 섬광, 깨달음). 장소가 바뀌면 fade, 시간만 바뀌면 wipe가 기본값.
- 효과: `shake`, `heavy_shake`(상하좌우·확대), `flash_white`, `flash_red`(붉은 비네트). 한 문장당 첫 읽기에서 한 번만 재생되며, 되감아 읽을 때는 재생하지 않는다.
- 분위기 색보정: tense / warm / sad / eerie / memory. tense·eerie는 비네트 추가.
- 날씨: `world.weather`의 비·눈·안개를 CSS 파티클 레이어로 표시(`weatherFor`).
- 배경의 느린 확대(12초)가 `vn-reader.css`의 1.2초 규칙에 덮여 사실상 꺼져 있던 문제를 수정했다. 카메라 확대(클로즈업)는 별도 `.vn-backdrop` 레이어로 분리했다.
- "화면 움직임: 최소화"와 OS의 동작 줄이기 설정에서는 효과·애니메이션을 끈다.

## 6. NVL 화자 표시

v12는 NVL에서 화자 이름을 숨겼고 `is-spoken` 클래스에 스타일이 없어 대사 줄과 서술 줄이 똑같았다. v13은 대사 줄 위에 작은 화자 이름표와 인물별 고정 색(`speakerHue`) 세로선을 붙인다. 인물 배치 확인으로 화자를 알게 된 줄은 지나간 줄에서도 이름을 유지한다. ADV 모드는 기존 이름 칸을 쓴다.

## 7. 소리

설정 → "환경음·분위기음"(기본 끔). 외부 음원 파일 없이 Web Audio로 합성한다.

- 환경음: 비, 실내 공기음, 야외 바람, 밤 풀벌레, 눈 오는 날의 바람. 날씨·장소 키워드·시간대로 선택(`ambienceFor`).
- 분위기음: tense / sad / warm / eerie / memory 화음 패드. 연출 `mood`에 따라 2초에 걸쳐 교차한다.
- 탭을 떠나거나 메인화면으로 가면 멈춘다. 브라우저 정책에 따라 첫 클릭·키 입력 뒤에 재생된다.

## 8. 사건 CG

설정 → "사건 CG"(기본 끔, 비용 추가). 모델이 `cg: true`로 표시한 문단의 첫 절정 비트에서, 이미 만든 배경과 현장 인물의 중립 입상을 참조로 16:9 이벤트 일러스트를 **문단당 최대 1장** 생성한다. 해당 비트부터 문단 끝까지 배경과 인물 대신 표시한다. 이미지 라우트의 기존 `scene` 용도를 쓰므로 비용 탭에서는 "장면"으로 집계된다.

## 9. 작품 타이틀 화면

작품을 열면 표지를 키 아트로 쓰는 타이틀 화면이 먼저 나온다: 시작하기/이어하기, 만난 인물, 설정, 작품 목록. "만난 인물"은 이 기기에서 이미 생성된 입상이 있는 인물만 보여 준다(아직 등장하지 않은 인물의 정체 노출 방지).

## 10. 코드 구조

- 새 모듈: `vn-stage.mjs`(무대 배치·날씨·연출 병합), `vn-sprite.mjs`(정규화·얼굴 합성), `vn-audio.mjs`(환경음). 순수 함수는 모두 단위 테스트가 있다.
- 쓰이지 않던 `.vn-portrait` 규칙과 v12 인물 배치 규칙(슬롯별 `right` 계산)을 삭제했다. v13 규칙은 `vn-reader.css` 끝의 V13 절에 모았다.

## 검증

- Node 테스트 149개 통과(기존 133 + 신규 16), `tsc --noEmit`, `npm run build` 성공.
- 브라우저 fixture: 가짜 Cortex 엔진 API + 실제 Cortex `CortexTurnExperience` + 합성 배경·입상 이미지 + 합성 인물 배치 응답으로 1280×720, 390×844에서 NVL·ADV, 비·눈, 클로즈업, 2인 배치, 화자 강조, 얼굴 합성, 사건 CG, 타이틀·만난 인물·설정 화면을 확인했다. 페이지 오류 없음.
- 실제 빌드된 `cortex.html`을 개발 서버에서 열어 새 모듈을 포함한 VN 셸이 `ready`까지 부팅하는 것을 확인했다(검증 환경에서 너름 네트워크가 막혀 작품 목록은 불러오지 못함).
- **확인하지 못한 것:** 실제 유료 모델로 생성한 입상·표정에서 얼굴 합성의 품질, 실제 모델이 연출 필드를 얼마나 적절히 채우는지, 환경음의 실제 청감(헤드리스 브라우저라 소리를 듣지 못함).

## v13.1 — 코드 검토 반영

v13 검토(2026-09-25)의 수정 권장 사항 네 가지를 모두 반영했다.

| 검토 항목 | 원인 | 수정 |
|---|---|---|
| 1. '만난 인물'이 아직 읽지 않은 인물을 보여 줌 | 이미지 캐시 유무로 판단. 다음 문단 이미지를 미리 만들기 때문에 캐시는 "만났다"는 증거가 아님 | 화면에 표시된 비트의 **검증된 현장 인물**만 작품별 읽기 기록(`dancheong-vn-met-v1:<작품>`)에 추가(`recordMet`). 갤러리는 이 기록만 사용하고, 이미지는 기록에 남긴 입상 키로 읽음. 이미지 선생성은 그대로 |
| 2. 사건 CG 실패가 정상 상태로 보이고 재시도로 복구되지 않음, 키 없이 저장된 CG를 읽지 못함 | `keysFor()`에 CG 키가 없어 상태·재시도·로드에서 빠짐 | CG를 선택형 자산 상태(`cgStatus`)로 분리. 실패 시 "사건 CG 생성 실패 · 다시 시도"를 표시하되 읽기는 막지 않음. `retry()`가 CG 실패도 지움. 생성하지 않는 경로(키 없음, `generate:false`)에서도 저장된 CG를 읽음 |
| 3. '표정 교체' 설정이 현재 입상에 즉시 적용되지 않음 | 원본 URL이 같으면 다시 그리지 않음 | 표시 키 = 교체 방식 + 중립 입상 + 표정 이미지. 비동기 결과 적용 때도 같은 키인지 확인. 큰 data URL을 DOM 속성에 두지 않도록 요소 속성으로 보관 |
| 4. '화면 움직임: 최소화'가 새 레이어에 적용되지 않음 | 최소화 규칙이 기존 배경·입상만 대상. 화자 튀는 동작(Web Animations)은 CSS로 멈추지 않음 | 최소화 시 무대·타이틀 안의 모든 transition·animation 제거. 화자 동작에 `motionReduced()` 확인 추가. 타이틀 화면에서도 설정이 적용되도록 시작 시점에 `data-motion` 설정 |

검증: Node 테스트 154개(신규 5개: CG 실패·재시도, 키 없는 CG 복원, 만난 인물 기록 규칙, 갤러리 기준, 움직임 최소화 규칙). 브라우저 fixture에서 실제 v13 화면 코드로 네 항목을 모두 재현한 뒤 수정을 확인했다.

- 2/7까지 읽은 상태: 다음 문단의 류진 입상은 미리 생성됐지만 갤러리에는 나디아만 표시.
- 얼굴만 교체 → 전체 이미지 저장 직후, 화면의 입상 이미지가 바로 바뀜.
- 최소화 저장 후 카메라·인물 레이어·인물·CG·날씨·배경의 계산된 transition 시간이 모두 0초.
- CG만 503으로 실패시킴 → 실패 안내 표시 → 안내를 눌러 재시도 → CG 요청 2회째에 표시.

기존 저장의 한계: v13.1 이전에는 만난 인물 기록이 없었으므로, 업데이트 직후의 갤러리는 비어 있고 이후 읽는 장면부터 채워진다.

## 남은 과제

- 인물별 자세 변형(2~3종)과 장면별 의상 교체: 캐시 키·참조 구조 변경이 커서 이번에는 프롬프트 개선까지만 했다.
- 표정 시트(3×3) 일괄 생성: 비용 구조 변경이 필요하다.
- 화자 쪽을 바라보도록 좌우 반전: 생성된 입상의 원래 시선 방향을 알 수 없고 비대칭 소품이 뒤집히는 문제가 있어 넣지 않았다.
- CSS 전체 재구성: 겹친 규칙 중 충돌·죽은 코드만 정리했다. 전체 재작성은 실제 화면 회귀 검사를 갖춘 뒤가 안전하다.
