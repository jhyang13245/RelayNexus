# v8 — 첫 문단 스트리밍 복원과 도입부 인물 누락 수정

2026-09-25. v7 공개 직후 사용자 피드백을 반영한 수정이다.

## 원인

1. **본문 지연:** v7의 페이지 수집이 `COMMITTED` 턴만 허용했다. Cortex는 이미 첫 문단을 공개하고 있었지만 비주얼노벨 화면은 전체 확정을 기다렸다.
2. **기성학원 인물 누락:** 출간 패키지 `start/opening.json`은 `openingCharacters` 문자열로 윤지훈·레나·릴리아를 지정한다. 런타임의 초기 `presentCharacterIds`에는 주인공만 들어갈 수 있었고, 화면은 그 배열만 참조했다.
3. **인물 표시의 배경 의존:** 인물 이미지가 완성돼도 독립 배경이 준비되지 않으면 인물 레이어를 비웠다.
4. **조용한 미생성 상태:** 이미지 키가 없으면 요청하지 않는 동작은 정상이지만, 화면에는 키 설정 안내가 없었다. 이후 사용자가 키를 입력한 뒤에는 배경 생성이 정상 작동하는 것을 확인했다.

## 수정

- 집필 중에는 Cortex의 공개용 `displayText`만 즉시 표시한다. 미확정 `turn.text` 내부 초안을 먼저 노출하지 않는다.
- 스트리밍 문자를 다시 타자 효과의 처음부터 재생하지 않는다. 후속 문단 도착과 턴 확정 시 현재 문장의 위치를 유지한다.
- 첫 문장 전의 대기와 읽으면서 다음 문장을 쓰는 상태를 구분한다. 생성 중에도 도착한 페이지를 넘길 수 있다.
- 자동 읽기는 도착한 문장을 읽고 스트림 끝에서 기다린다. 새 턴이나 선택지를 자동 제출하지 않는다.
- 도입부 표시에서 명시된 `openingCharacters`를 추가로 해석한다. 공개 가능한 인물만 사용하고 원본 정사 상태를 수정하지 않는다. 도입 이후의 턴에 이 목록을 계속 적용하지 않는다.
- 이미 저장된 구버전 도입부의 표시 정보는 v2로 갱신한다. 배경·인물 이미지의 기존 캐시 키는 유지한다.
- 완성된 인물은 배경 생성의 성공 여부와 관계없이 표시한다.
- 키 미입력, 이미지 준비 중, 생성 실패를 표시하고 설정 또는 재시도 버튼으로 연결한다.

## 확인

- 총 85개 단위·회귀 검사 통과, TypeScript 검사 통과.
- 브라우저 fixture에서 `STREAMING` 상태의 첫 글자와 첫 문단 표시를 확인했다. 내부에 둔 미공개 초안은 표시되지 않았다.
- 후속 문단이 도착해도 1/3에 머물렀고, 2/3을 읽는 중 `COMMITTED`가 되어도 2/3을 유지했다.
- 배경만 실패시킨 fixture에서도 인물 이미지가 보였다.
- 별도 Muse 작업 사본에서 작성한 16개 회귀 검사는 주 개발자가 직접 읽고 실행한 뒤 통합했다. 원본 모듈 변경은 없었다.

v7의 전체 확정 대기 설명은 이 버전에서 대체된다. 이미지 생성 시간과 모델의 첫 응답 시간 자체를 줄인 변경은 아니며, 기존에 먼저 공개되는 문장을 바로 읽을 수 있게 한 수정이다.
