# v13.12.1 — 음성·음악 수정과 덧칠 관리

## 수정한 문제

- 곡 분석 결과를 별도 레코드에 저장합니다. 교체·연결 해제 후 늦게 끝난 분석이 곡을 되살리거나 새 곡을 덮어쓰지 않습니다.
- 음악 생성 시작 당시의 작품과 분위기를 고정합니다. 작품을 바꾸더라도 완료된 유료 결과는 요청한 작품에 저장하고, 다음 곡 생성은 중단합니다.
- 같은 대사의 뒤에 연기 지시 서술이 스트리밍되어도 재생 중인 대사를 중단하거나 중복 요청하지 않습니다. 명시적인 다시 듣기는 최신 지시를 사용합니다.
- 음성 분석 캐시를 전체 오디오 데이터로 구분합니다. 길이와 끝 무음이 같은 다른 음성의 시작·종료 지점을 혼동하지 않습니다.
- 음악의 음량·반복 구간 분석을 Web Worker에서 수행합니다. Worker를 사용할 수 없으면 UI에서 무거운 분석을 하지 않고 기본 재생으로 대체합니다.
- `3마리`, `2가지` 등의 수량을 `세 마리`, `두 가지`로 읽습니다.

## 작품 덧칠 적용

1. 작품 메인화면에서 **덧칠 관리**를 엽니다. 너름의 공개 덧칠 번호·날짜·변경 설명을 조회합니다. 관리 창을 열거나 **새로 확인**을 누르면 최신 목록을 가져옵니다.
2. 설치하지 않은 덧칠은 **이 덧칠로 새 이야기 시작**으로 적용합니다. 현재 진행은 별도 자동 보관소에 저장하며, 10개 수동 저장 슬롯을 덮어쓰지 않습니다.
3. 이전 덧칠은 **보관된 이야기 이어하기**로 돌아갑니다. 본문·사건 상태·읽던 위치·만난 인물 기록을 함께 복원합니다.
4. 자동 보관된 이야기도 **파일로 백업**할 수 있습니다. 현재 이야기의 백업은 먼저 최신 진행을 저장합니다. 백업 파일은 기존 저장·불러오기 창의 가져오기로 복원합니다.

공개된 덧칠 번호와 SHA-256을 함께 저장하고, 지정한 번호의 불변 다운로드 주소를 사용합니다. 파일 지문·크기가 다르거나 검증에 실패하면 현재 진행을 바꾸지 않습니다. 전환 도중 화면 저장에 실패하면 기존 저장 슬롯과 같은 복구 저널로 다음 실행에서 마무리합니다.

덧칠별 사건·인물 설정이 달라질 수 있으므로 진행 중인 이야기에 새로운 패키지를 강제로 합치지 않습니다. 작품 제목이나 인물 이름만 보고 상태를 이어 붙이지도 않습니다. 새 덧칠의 이미지는 별도 캐시를 쓰며, 다른 덧칠의 인물 고정·기준 이미지를 자동으로 사용하지 않습니다. 이전 덧칠의 이미지·음성·비용 기록은 지우지 않습니다. 새 이야기에서 이미지·음성 기능을 켜고 사용하면 기존 설정에 따라 생성 비용이 발생합니다.

업데이트 전 저장에는 덧칠 지문이 없으므로 **기존 진행 · 덧칠 번호 미확인**으로 보존합니다. 최신 덧칠로 임의 판정하지 않습니다. 자동 보관소는 기기 브라우저 저장이며, 다른 기기 이동과 별도 보존에는 파일 백업이 필요합니다. 새로하기는 현재 선택된 덧칠을 다시 시작하므로 같은 덧칠의 이전 진행을 남기려면 먼저 수동 슬롯에 저장합니다.

## 검증

- Node 테스트 **389개 통과**. 음원 교체 중 늦게 끝난 분석, 작품 전환 중 음악 생성, 스트리밍 음성 중복 요청, 음성 캐시 충돌 재현 포함.
- 실제 Worker 모듈 실행 및 재생용 PCM 버퍼 보존 검증.
- 덧칠 원본 불일치 차단, 구버전 저장 호환성, 위치·인물 기록 분리, 다른 덧칠 입상 혼합 차단, 백업 왕복, 중단된 활성화 복구 검증.
- 로컬 미리보기에서 크로노스 코어 v3 → v2 → v3 전환, 자동 보관 목록, 새로고침 후 복원 및 모바일 가로·세로 화면 확인.
- 실결제 이미지·음성·음악 API는 이번 회귀 검증에서 호출하지 않았습니다. 제공자별 실제 생성 품질·응답 시간은 미검증입니다.
- Cortex 원본 HTML은 수정하지 않았습니다.
