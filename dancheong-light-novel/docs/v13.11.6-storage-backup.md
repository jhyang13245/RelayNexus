# v13.11.6 — 저장 보호, 파일 백업, 캐시 관리

## 사용 방법

- 첫 슬롯 저장·파일 가져오기 또는 첫 이미지/음성 API 요청 때 `navigator.storage.persist()`를 한 번 요청합니다. 읽기/생성을 기다리게 하지 않습니다. 승인 여부는 브라우저가 결정하며, 거절/미지원이면 파일 백업을 안내합니다. 저장 창과 설정에서 수동 재요청할 수 있습니다.
- 저장·불러오기 창에서 사이트 전체 사용량과 브라우저 허용량(estimate), 영구 저장 승인 여부, 슬롯별 예상 크기를 표시합니다. 이전 버전 슬롯은 다음 저장부터 크기를 기록합니다.
- 각 슬롯의 **파일 내보내기**는 진행/패키지/읽기 위치/인물 상태, 같은 작품·story 범위의 VN 이미지·음성·연출 캐시, 작품 비용 기록을 포함합니다. 키·연결 설정은 내보내지 않습니다. 서버 업로드 없이 기기에서 만듭니다.
- **파일 가져오기**는 검사 후 선택한 슬롯에 전체 파일 내용을 한 번의 IndexedDB 트랜잭션으로 보관합니다. 기존 슬롯이면 덮어쓰기 확인을 거칩니다. 실제 플레이는 해당 슬롯의 **불러오기**를 눌러야 바뀝니다. 기존 엔진의 원자적 가져오기와 복구 저널을 재사용합니다.
- 파일을 불러올 때 VN 캐시와 비용 기록은 없는 key/id만 추가합니다. 새 자산과 실제 비용 기록을 덮어쓰거나 비용을 두 번 합산하지 않습니다. 캐시 복원 실패 시에도 슬롯 안의 백업 복사본이 남습니다.
- 설정 → **저장 공간**에서 작품별 이미지/AI 음성 캐시를 확인하고 따로 정리합니다. 삭제 대상과 되돌릴 수 없다는 점을 확인한 뒤 삭제합니다. 이어하기·슬롯·엔진 패키지 원본·비용 기록은 유지합니다. 파일에서 가져온 슬롯에 포함된 미디어 복사본도 유지하므로 용량이 즉시 모두 줄지는 않습니다.
- 캐시 정리 후 해당 작품/종류의 자동 생성을 일시 중지합니다. 같은 화면에서 다시 켤 수 있으며, 재생성 시 과금될 수 있음을 안내합니다. 다른 탭에도 중지 상태와 메모리 무효화를 전달합니다.
- 이미지 준비/수정, 음성 생성 중에는 Web Locks 공유 잠금을 잡습니다. 캐시 정리는 배타적 잠금을 즉시 획득할 수 있을 때만 수행해 진행 중인 유료 결과가 삭제 뒤 다시 기록되는 경합을 막습니다.
- 음성 메모리 캐시는 최근 사용 48개 LRU입니다. 밀려난 음성은 IndexedDB에서 다시 읽고 유료 재생성을 하지 않습니다. 키가 없어도 저장된 음성은 재생할 수 있습니다.

## 형식과 제한

- 파일 형식은 `DANCHEONG_VN_FILE_V1`, SHA-256 손상 검사와 gzip 압축(지원되는 브라우저)을 사용합니다. JSON도 가져올 수 있습니다. 체크섬은 파일 손상 검사이며 외부 발행자의 신원 인증은 아닙니다.
- 읽기/압축 해제 한도는 256 MB입니다. 초과 파일은 명시적 오류로 중단하고 기존 데이터를 유지합니다. 큰 파일은 만들기/가져오기에 시간이 걸릴 수 있습니다.
- persistence 승인은 기기 분실이나 사용자가 브라우저 데이터를 직접 지우는 상황을 막지 못합니다. 파일을 실제 다운로드했는지 확인하고 기기 밖에도 보관해야 합니다. 클라우드 동기화 기능은 아닙니다.
- Web Locks 미지원 브라우저에서는 안전한 캐시 정리를 중단하고 이유를 표시합니다. 이미지/음성 생성과 슬롯 파일 보관·복원은 계속 가능합니다. 파일의 미디어 복원은 기존 데이터에 없는 항목만 추가합니다.
- 슬롯 전체 백업 구조는 유지합니다. 10개 슬롯 간 패키지 중복 제거/공유 blob 저장소로의 이관은 이 릴리스에 포함하지 않았습니다. 저장량과 슬롯 크기로 중복에 따른 용량을 확인할 수 있습니다.

## 검증

- Node 자동 검사: 저장 보호 승인/거절/미지원, 스키마별 작품 범위, gzip 왕복과 API 키 제외, 원래 저장 시각 보존, 체크섬/다른 작품/외부 URL/초과 크기 거부, 저장 실패 시 원본 슬롯 보존, 음성 48개 LRU·기기 캐시 재사용.
- 별도 localhost 기원의 실제 엔진/실제 작품 패키지로 파일을 다운로드하고 2번 슬롯에 가져오기 → 이미지·음성 시험 캐시 삭제 → 파일 슬롯 불러오기 → 본문·이미지·음성 복원을 확인했습니다. 다른 작품 캐시는 유지되고 비용은 원래 1회 그대로였습니다. 실제 사용자 진행이나 키는 사용하지 않았습니다.
- 390×844 세로와 844×390 가로 화면에서 저장 확인창, 4개 슬롯 버튼, 설정의 저장 공간 패널/캐시 확인 UI를 확인했습니다.
- Muse는 분리된 복사본에서 저장 UI CSS만 작성했습니다. 허용 파일 외 변경이 없음을 확인하고 메인 개발자가 CSS 전체를 검토하고 실제 렌더링을 확인했습니다. 저장·파일·삭제·동시성 로직은 메인 개발자가 구현했습니다.
- 실제 Safari의 장기 미방문 데이터 정리, 실제 디스크 고갈, 수백 MB 파일의 기기별 메모리 한계는 재현하지 않았습니다. 승인 실패와 저장 실패는 자동 검사로 다뤘습니다.
