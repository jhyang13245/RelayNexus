# v1.25.3 · 통합 VN의 사건별 인물 호칭

## 재현과 원인

Chrome Fate/Seoul에서 ‘정체불명의 뇌전 사용자’ 사건의 ‘남자’ 호칭이 등록 인물과 연결되지 않아 완전 자동이 중단된 것을 확인했다. 독립판은 `fate-seoul` 슬러그로 검토된 사건별 공개 호칭표를 읽지만, 본사이트의 저장 범위는 `main-…` 해시여서 같은 표를 찾지 못했다.

## 수정

- 저장 범위와 작품 식별을 분리했다. 해시 범위에서도 검토된 작품의 인물 ID 3개와 사건 ID 4개가 모두 일치할 때 기존 호칭표를 적용한다. 제목, 성별, 외형, 등장인원 수로 추측하지 않는다.
- 여러 표에 동시에 일치하거나 식별 정보가 부족하면 호환표를 적용하지 않는다. 작품 패키지에서 지정한 공개 호칭과 빈 배열을 포함한 명시적 재정의가 우선한다.
- 호칭은 해당 턴의 사건 범위에서만 유효하다. 구형 턴의 `txn.eventId`를 지원하되 최신 사건 ID를 과거 턴에 대신 넣지 않는다.
- 기본 입상이 없어도 공개 외형과 첫 등장 허용 조건을 만족한 인물은 기존 생성 경로로 준비한다. 비공개 이름을 판정·이미지 요청에 노출하지 않는다.
- ‘호칭 연결 필요’ 상태 버튼을 누르면 실제 작품·성능 점검 창을 연다.
- 자동 진행의 인물 표시 확인을 유지한다. 확실하지 않은 인물을 임의로 그려 넣거나 확인을 건너뛰지 않는다.

## 확인

실제 Cortex 공개정보 처리기를 사용하는 합성 시나리오로 해시 범위의 등록 인물 후보 → 화자 판정 → 내장 이미지 없는 인물의 새 입상 요청 → 자동 진행 표시 조건 통과를 검사했다. 타 사건 재사용 금지, 비공개/조건부 공개 차단, 작가의 호칭 재정의, 기존 입상 캐시 키 유지도 확인한다. 사용자의 플레이 본문·원본 패키지·API 키를 테스트 파일에 넣지 않았다.
