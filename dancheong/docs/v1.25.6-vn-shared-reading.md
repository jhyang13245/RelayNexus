# v1.25.6 — 멀티 VN 공통 읽기

## 변경

- 방마다 문단 위치와 표시 시작 시간을 하나만 저장한다. 가장 먼저 준비된 참가자의 요청을 서버가 채택하고, 모든 참가자가 같은 시각을 기준으로 글자를 표시한다.
- 인물 준비에는 기존 5초 상한을 적용한다. 공통 표시가 시작된 뒤에는 각 기기의 이미지·음성 준비 속도가 문장 시계를 지연시키지 않는다.
- 확정된 비트만 첫 터치로 전체 문장 표시, 다음 터치로 다음 문단 이동이 가능하다. 이동은 방 전체에 적용된다. 작성·판정 중에는 수동 이동을 서버에서도 거부한다.
- 동시 요청은 순번 비교로 한 번만 적용한다. 요청 실패를 별도 큐에 쌓거나 나중 문단에서 재생하지 않는다.
- 입력 담당자 변경과 공식 기록 재적용 중에도 턴 ID와 문단 시작 위치를 유지한다. 임시 본문이 사라지는 동안 기존 화면을 보존하고, 복원이 끝나면 같은 위치를 연결한다.
- 공통 읽기가 끝난 뒤 다음 플레이어의 입력 제한 시간을 새로 시작한다. 유료 생성은 기존대로 해당 비트를 작성한 플레이어의 키를 사용한다.

## 성능·저장

- 기존 상태 확인 응답에 작은 읽기 프레임을 함께 전달한다. 글자별 네트워크 요청이나 별도 상태 확인 루프는 없다. VN 상태 확인은 한 요청씩 800ms 간격으로 진행한다.
- `multiplayer_vn_playback`에 방당 한 행만 유지한다. 본문·API 키는 포함하지 않는다. 기존 방의 문단 정보는 한 번 변환하며, 이후 문단 이동에 전체 저장 파일을 다시 내려받지 않는다.
- 이전 비트의 파싱 결과는 재사용한다. 일반 확인에서는 마지막 비트만 검사하며, 복원·수정 이벤트 때만 이전 비트를 다시 확인한다. 화면 파생 캐시도 상한을 둔다.

## 검증과 한계

- 서버 테스트: 최초 준비 경합, 동시 터치, 오래된 요청, 판정 전 터치 거부, 자동 진행, 턴 인계, 참가자 권한 및 기존 유료 자산 담당자 규칙.
- 렌더러 테스트: 10문단 앞에서 턴 인계 후 같은 위치 복원, 임시 본문 공백, 확정 문장 터치, 서로 다른 시계에서 10,000프레임 진행, 1,000비트/10,000회 확인.
- 로컬 Chrome에서 실제 통합 렌더러 두 개를 가로/세로 크기로 열고 개인 표시 속도와 전달 지연을 다르게 하여 공통 문단·글자 위치 및 인계 복원을 확인했다. 실제 사용자 이야기나 유료 API 호출은 사용하지 않았다.
- 네트워크 단절 중인 기기까지 동시에 표시할 수는 없다. 연결이 복구되면 현재 방의 위치를 따라잡는다. 1.2초의 전환 준비 시간을 두어 일반적인 전달 지연을 흡수한다.
- 실제 여러 휴대폰을 사용한 장시간 실방 플레이와 iOS 기기 검증은 수행하지 않았다.
