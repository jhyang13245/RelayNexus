# 비주얼노벨 무대 연출 확장 — 1.26.0

월희 리메이크급 상업 비주얼노벨과 비교해 따라잡을 수 있는 연출 차이 가운데 8개 항목(1·2·3·4·6·7·8·10)을 구현했습니다. 작품별 시각 모티프(5), 게임 장치(배드엔드·힌트·플로차트·용어집, 9), 작품별 UI 스킨·오프닝(11)은 이번 범위에서 제외했습니다.

## 비용 원칙

- 새 유료 API 호출은 없습니다. 연출 지시는 기존 인물 판정(캐스트) 요청 한 번에 `stagecraft` 필드로 함께 받습니다. 늘어나는 것은 그 응답의 출력 토큰뿐입니다.
- 액션 컷·클로즈업·깊이 연출은 이미 화면에 있는 배경·입상·이벤트 CG와 그 잘라낸 부분만 씁니다. 새 이미지를 그리지 않습니다.
- 음악 스팅어·캐릭터 테마·액션 효과음은 브라우저에서 합성하고, 녹음 효과음은 함께 배포하는 CC0 파일을 씁니다.
- 예외: `작품 아트 규칙`을 바꿔 저장하면 기존 스타일 메모와 같은 규칙으로 새 이미지 키가 만들어져 이후 이미지를 다시 그립니다(이미지 비용 발생). 기본값은 `자동`이며 기존 사용자에게 자동 적용되지 않습니다.
- 저장된 캐스트 판정에는 `stagecraft`가 없으므로 그대로 유효하며, 그 문단은 평범한 연출로 표시됩니다(재구매 없음).

## 구현 항목

### 1. 텍스트 연출
- `stagecraft.marks`: 본문에 그대로 있는 단어·구(최대 2개, 24자)에 색(진홍·금·청), 크기(크게·작게), 떨림, 사라짐 효과를 겁니다. 떨림은 글자별로 따로 흔들립니다.
- `stagecraft.layout: "center"`: 60자 이하 한 줄을 검은 화면 중앙에 단독으로 띄웁니다(이전 줄·화자명·입상 숨김).
- `stagecraft.tempo`: `slow`는 한 글자씩 느리게, `halting`은 쉼표·말줄임표에서 끊어 타자합니다. 효과가 걸린 구는 자동으로 느리게 찍힙니다.
- 판정: 본문에 없는 구, 허용 외 스타일, 긴 줄의 중앙 배치, 구두점 없는 halting은 버립니다.

### 2. 전투·긴장 연출
- 속도선, 집중선(초점 인물 위치 기준), 2~3분할 만화 컷(초점 인물 얼굴 크롭·배경 확대·상대 얼굴), 흑백 반전 임팩트, 적색 점멸, 슬로모션, 연속 컷(배경·얼굴 크롭 4장).
- 앵커 문구가 화면에 찍히는 순간 기존 연출 시계(효과음·충격과 같은 시계)로 실행합니다. 다시 읽기·건너뛰기·빨리 넘기기에는 재생하지 않습니다.
- 물리 액션(속도선·분할·반전·점멸·연속 컷)은 서술문(대사 제외)의 현재 문장이어야 하고 행동 어휘가 있어야 합니다. 회상·꿈·상상 문장은 거부합니다. 강조 카드가 있는 줄에는 액션을 겹치지 않습니다.
- 광과민성: 반전·점멸은 1초에 2회 이하로 깜박입니다. `동작 줄이기`(앱 설정 또는 OS)에서는 움직이는 레이어를 모두 끕니다.

### 3. 2.5D 깊이
- 배경을 기기에서 저해상도(160px)로 분석해 깊이 지도를 만듭니다(세로 위치·국소 대비·채도·안개 단서의 휴리스틱이며 신경망 모델이 아닙니다). 원·중·근 3층의 부드러운 마스크로 나눕니다.
- 포인터 위치에 따른 시차, 느린 자동 드리프트(동작 줄이기에서 끔), 대화 중 배경 피사계심도 흐림을 적용합니다. 이벤트 CG와 표지 이미지는 층을 나누지 않습니다.

### 4. CG 카메라
- 이벤트 CG가 처음 표시되면 와이드 → 얼굴(또는 손) 영역 클로즈업 → 두 번째 영역 → 와이드 순서로 움직인 뒤 느린 켄 번즈로 이어집니다. 다시 볼 때는 켄 번즈만 합니다.
- 얼굴·손 영역은 기기에서 피부색 연결 영역으로 찾고, 없으면 가장 세밀한 영역을 씁니다. 화면 가장자리가 드러나지 않게 이동 범위를 제한합니다.

### 6. 그림 톤 통일
- 작품 아트 규칙(팔레트·선·음영)을 `설정 → 연출 → 무대 연출 확장`에서 고르고 `저장`하면 배경·입상·CG의 모든 생성 프롬프트에 같은 규칙이 들어갑니다.
- 공통 색보정: 배경·입상·CG·컷인 전체에 같은 톤 커브·채도·분할 톤을 화면에서 적용합니다(약하게/강하게/끔, 비용 없음). 팔레트를 고르면 그 팔레트의 색보정을 씁니다.
- CG·입상 일관성 점검: 이벤트 CG에 참여 인물 입상의 뚜렷한 머리색이 보이지 않으면 화면 상단에 알림을 띄웁니다. 검정·갈색·흰머리처럼 흔한 색은 판단하지 않습니다. 자동 재생성은 하지 않습니다.

### 7. 음악
- 캐릭터 테마: 작품·인물마다 고정된 5~7음 모티프를 만들어 첫 만남과, 감독이 `leitmotif: "focus"`로 지정한 결정적 순간에 재생합니다(15초 간격 제한).
- 전투곡: 음악 큐 `battle`을 추가했습니다. 기본 음악(절차 생성)은 전투 패턴을, AI 트랙 모드는 `전투` 트랙(없으면 `긴장` 트랙)을 씁니다.
- 스팅어: 충격·폭로·상실·결의의 짧은 음악을 앵커 문구 순간에 재생합니다.
- 동기화: 강조 카드와 충격 순간 배경음악을 잠시 낮추고, 같은 줄에 연출 큐가 있으면 음악 전환을 그 큐에 맞춰 들어갑니다(최대 6초 대기).

### 8. 녹음 효과음
- `public/vn-sfx/`에 CC0 녹음 효과음 17개(충격·폭발·금속·문·눈 위 발소리)를 넣었습니다. 출처와 SHA-256은 `manifest.json`과 `CREDITS.md`에 있습니다.
- 녹음 음원이 없는 종류(천·종이, 일반 발소리)와 Ogg를 해독하지 못하는 브라우저에서는 기존 합성 효과음으로 재생합니다. 설정에서 `합성음`으로 바꿀 수 있습니다.
- 이 개발 환경에서는 외부 음원 사이트 접근이 막혀 있어, CC0로 명시된 GitHub 저장소(Minetest Game의 CC0 표기 파일, Kenney Starter Kit Racing)에서만 골랐습니다. 새 CC0 파일은 `manifest.json`에 경로를 추가하면 바로 쓰입니다.

### 10. 대기 연출
- 5초 대사 대기와 다음 턴 대기·스트리밍 동안 배경을 천천히 밀고 비네트가 숨 쉬듯 움직입니다.
- 다음 턴을 기다릴 때 같은 장면에서 본 이벤트 CG가 있으면 흐린 회상 레이어로 천천히 보여 줍니다.

## 설정

`설정 → 연출 → 무대 연출 확장`: 텍스트 효과, 액션 연출, 2.5D 배경 깊이, CG 카메라, 대기 연출, 공통 색보정, 음악 스팅어, 캐릭터 테마, 효과음 음원, CG·입상 일관성 점검, 작품 아트 규칙. 아트 규칙 외 항목은 바로 적용되고 이 기기에 저장됩니다. 기존 `연출 효과` 끔 상태에서는 무대 연출 확장도 꺼집니다.

## 구조

- 원본 `vendor/visual-novel/public/*`은 수정하지 않았습니다. 모든 연결은 `vendor/visual-novel/nexus-stagecraft-adapter.mjs`가 빌드 때 적용합니다.
- `public/cortex-vn-stagecraft.mjs`: 스키마·판정·큐·타자 속도·음악 동기화·모티프·깊이/영역/색 분석·아트 규칙·색보정(순수 함수).
- `public/cortex-vn-stagecraft-dom.mjs`: 화면 레이어와 설정 UI.
- `public/cortex-vn-sound.mjs`: 덕킹, 스팅어·모티프·휙 소리 합성, 녹음 효과음 재생.
- `public/cortex-vn-stagecraft.css`, `public/vn-sfx/`.

## 검증

- `tests/cortex/vn-stagecraft.test.mjs`: 판정, 큐 시계, 타입셋, 타자 속도, 압축 캐스트 요청, 전투 음악, 음악 동기화, 모티프, 깊이·영역·색 점검, 아트 규칙, 덕킹, 녹음 효과음 대체 재생, 화면 런타임, CC0 파일 해시, 빌드 연결.
- 전체: `npm run build`, `npm run test:unit`, 렌더 테스트, `test:cortex-replay`, `node --test tests/cortex/*.test.mjs`, `tsc --noEmit`.
- 브라우저(Chromium): 합성 장면에서 모든 액션 레이어·중앙 한 줄·깊이·CG 카메라·대기 연출의 화면을 확인했고, 실제 `reader.mjs` 번들 초기화와 설정 화면(PC·모바일)을 오류 없이 확인했습니다.

## 한계

- 깊이는 휴리스틱 추정이라 복잡한 구도에서 층 경계가 어긋날 수 있어 시차 폭을 작게(최대 16px) 두었습니다.
- 얼굴 영역은 피부색 기반이라 피부가 드러나지 않거나 비현실적 피부색 인물은 찾지 못하고 가장 세밀한 영역으로 대신합니다.
- 일관성 점검은 머리색만 봅니다. 얼굴 생김새 비교는 하지 않습니다.
- 실제 LLM이 새 필드를 얼마나 자주·정확히 채우는지는 유료 호출 검증을 하지 않았습니다. 판정기가 근거 없는 지시를 버리므로 잘못된 지시는 평범한 연출로 떨어집니다.
