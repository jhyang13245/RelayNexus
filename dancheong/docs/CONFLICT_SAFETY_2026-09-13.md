# 저장·동기화·멀티플레이 충돌 보강

기준 소스: `deba93bfec00be9f587f5130a7a4b8a4a80f4546`.
기존 기능과 저장 형식을 유지하며 전면 검토에서 재현한 결함을 수정했다.

## 재현 결함별 조치

1. **서로 다른 클라우드 진행 덮어쓰기**: 409 응답으로 로컬 본문을 복원/교체하지 않는다. 진행 중 비트를 마친 최신 로컬 저장본을 독립적인 `충돌 보존` 세션에 저장하고 원래 세션도 유지한다. 보존 요청은 동일 ID 재시도에 멱등적이며 원래 행을 수정할 수 없다.
2. **기기 사용권 없는 저장**: 서버가 소유자·기기·사용권 세대(epoch)·만료 시각을 확인한다. 객체 업로드 후 실제 SQL 갱신 시에도 다시 검사한다. 같은 기기의 살아 있는 사용권은 공유하고, 만료/기기 변경 때 세대를 교체한다. 오래된 탭의 종료 요청이 새 탭의 사용권을 해제하지 못한다.
3. **이미지만 추가된 기록의 동기화 누락**: 실제 영속 저장 성공을 호스트에 알리고 클라우드 내보내기를 요청한다. 내보내기 자체는 변경 알림을 발생시키지 않아 순환 저장을 방지한다. 내보내기가 시작할 때의 저장 시각을 ACK에 사용하며, 저장 실패를 완료로 표시하지 않는다.
4. **R2 읽기/교체 경합**: 읽던 객체가 동시 저장으로 교체되면 최신 리비전의 포인터와 요약을 함께 다시 읽는다. 해시 검증은 유지한다.
5. **호스트 Reader의 평문 API 키 중복 저장**: 기존 암호화 키 보관 체계를 유지하고 Reader의 레거시 평문 키 저장 슬롯만 차단/정리한다. 작품·세션·이미지 저장소와 독립 실행 엔진의 저장 정책은 건드리지 않는다.
6. **멀티 준비 취소/시작 경합**: 시작을 확정하는 SQL에서 참여자 수, 전원 준비 상태와 키 준비 상태를 원자적으로 재검사한다. 준비 취소가 먼저 반영되면 시작하지 않으며 재시도 안내를 제공한다.

## 함께 보강한 경계

- 클라우드 ACK의 리비전은 해당 요청이 실제 저장한 리비전이다. 뒤이어 끝난 다른 저장의 리비전을 잘못 반환하지 않는다.
- 로컬 원문을 최신 클라우드로 교체하기 전 이전 업로드/복원 ACK의 저장 시각을 대조한다. 비트 수나 기기 시계만으로 동일 계보라고 추정하지 않는다. 기존 ACK가 없는 이전 버전 기록은 보수적으로 충돌 보존 경로를 탈 수 있다.
- 클라우드 조회 중 새 입력 또는 이미지 저장이 생겨도 그 기록을 원격 다운로드로 덮어쓰지 않는다. 작성 중이면 완료 후 내보낸다.
- 인계받은 동일 세션과 사용자가 명시적으로 만든 분기 세션의 초기 리비전을 구분한다. 새 분기는 복원 완료 후 즉시 클라우드 저장을 요청한다.
- 클라우드 목록 조회는 15초 기한 후 공유 요청을 해제해 다음 조회가 가능하다.
- 삭제 의도를 보존하고 서버 확인 전까지 실제 로컬 복구 데이터는 유지한다. 오래된 목록 응답이 삭제한 카드를 되살리지 않는다. 통신 실패는 삭제 대기로 알린다.
- 멀티플레이 설정/복원/키 해제 후에도 사용자의 테마·글씨 크기·본문 폭·표시 속도와 선택한 모델·추론 강도를 유지한다.
- 큰 JSON의 해시 계산은 작은 UTF-8 청크로 처리하고 중복 파싱/인코딩을 줄인다. 무결성 검증과 기존 용량 상한은 유지한다.
- 실제 제품 코드의 TypeScript 검사를 통과하도록 누락/불일치 타입을 보완했다. 생성물·이전 버전 보관본·테스트는 제품 타입 검사에서 분리하고 각각 기존 테스트로 검증한다.

## 적용과 검증 한계

- 스키마 변경은 생성된 `0013_perfect_microchip.sql`의 `epoch` 열 추가뿐이다. 기존 마이그레이션·사용자 작품·본문·이미지 데이터를 재작성하거나 삭제하지 않는다.
- 이전 클라이언트에는 새 기기 사용권 정보가 없으므로 배포 후 PC와 휴대폰에서 진행 저장을 확인한 뒤 새로고침해야 한다. 구버전 미전송 기록은 지우지 말고 보존한다.
- iPhone/Android 실기기 두 대의 동시 실행, 운영 환경의 강제 종료·오프라인 전환 및 실제 유료 모델 호출을 직접 검증한 것은 아니다.
- 큰 저장본의 불필요한 메모리 복사는 줄였지만 80MiB 저장본의 운영 Worker 동시 요청 스트레스 테스트까지 통과했다고 주장하지 않는다. 전체 JSON을 읽는 기존 방식의 메모리 한계는 남는다.
- 응답 대기 중인 모바일 앱을 OS가 종료하면 실행 중 네트워크가 보장되지는 않는다. 로컬 저장과 재시도/충돌 보존을 강화한 것이며 강제 종료 후 서버 업로드를 보장하는 백그라운드 서비스는 아니다.
