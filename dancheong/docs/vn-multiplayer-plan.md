# 비주얼노벨 멀티플레이 · v1.25.1

2026-09-28. 이전 설계 문서를 실제 구현 기준으로 갱신했다.

## 방 규칙

- 방장이 생성할 때 소설/비주얼노벨을 선택한다. 방을 만든 뒤 바꿀 수 없다. 기존 방은 소설 모드를 유지한다.
- Cortex 방에서 VN을 지원한다. 기존 Lotus 방은 소설 모드다.
- 같은 방은 같은 본문·판정·작중 시간을 사용한다. 읽는 위치, 표시 속도, 음성 ON/OFF는 각 기기가 정한다.
- 입력 권한, 제한시간, 방장 대행, 재접속, 판정 및 저장은 기존 Cortex 멀티플레이 프로토콜을 사용한다.
- 일반 자동 읽기는 개인별로 사용할 수 있다. 개인 완전 자동 진행과 저장 슬롯/되돌리기는 공유 기록에 적용하지 않는다. 방의 제한시간 자동 진행은 유지한다.

## 입력과 채팅

- VN 채팅 버튼은 기존 RoomChat을 연다. 증분 채팅 조회, 낙관적 전송/재시도, IME 처리, 스크롤 유지, 안 읽은 메시지와 작은 알림을 재사용한다.
- 서버가 수락한 입력을 작성자 이름과 함께 모든 참가자 오른쪽에 10초 동안 표시한다. 모바일 세로에서는 오른쪽 하단 안전 영역 위에 작게 배치한다.
- 서버 시각 기준으로 남은 시간을 계산한다. 중복 수신은 표시 시간을 늘리지 않는다. 재접속한 사람에게 지난 입력을 다시 10초 노출하지 않는다.
- 입력 중 초안과 수락된 행동은 별도다. 초안은 인물·이미지 생성의 근거로 쓰지 않는다.

## 본문·자산 전송

- 공개된 displayText와 공개 화자 표기만 보내고 엔진 초안은 전송하지 않는다. 개인 화면용 임시 턴은 엔진의 정본 턴 목록을 변경하지 않는다.
- 기존 순번·기준 revision·권한 검증과 실패 시 전체 복구를 유지한다. VN 본문도 늘어난 부분만 전송한다. 잘못된 기준이나 수정된 앞부분은 전체 프레임으로 복구한다.
- 확정 시 같은 작품의 화면을 다시 초기화하지 않는다. 읽던 문장과 타자 출력 위치를 유지하고 확정 기록을 이어 받는다.
- 개인 커서/음량 등이 담긴 runtime.vnPresentation은 공유 저장에서 제외한다.
- 이미지·음성·인물 판정은 정본 저장과 별개인 방별 자산 저장소를 쓴다. D1은 작업 상태, R2는 개별 자산 JSON을 저장한다. 정본 저장마다 이미지 data URL을 반복 전송하지 않는다.
- 동일 종류/논리 키의 요청은 서버의 원자적 claim으로 한 참가자만 실행한다. 준비된 자산은 인증된 방 참가자끼리 공유하고, 화자 근거 검증은 받는 기기에서도 유지한다.
- 방의 동시 자산 생성은 최대 3개다. 대기는 작은 상태 조회로 묶고, 숨긴 탭은 폴링/선행 준비를 멈춘다. 본문 차례 권한은 이미지 완료를 기다리지 않는다.
- 기기의 기존 이미지/음성 캐시를 재사용한다. 한 번 생산한 결과의 업로드 재시도에서 유료 생성 함수를 다시 실행하지 않는다.

## 키와 비용

- 각 참가자는 자신의 본문·이미지·음성 키만 사용한다. 키는 자산 또는 다른 참가자에게 보내지 않는다.
- 해당 턴의 집필 담당자가 인물·연출 판정, 모든 이미지(배경·입상·표정·사건·동작), 음성 비용을 부담한다. 서버는 진행 중인 집필 임대 또는 확정 턴의 비용 영수증으로 담당자를 검증한다. 턴 전환 후 뒤늦게 요청되는 자산도 원래 담당자만 생성한다. 오프닝 및 방 생성 이전의 가져온 기록은 방장 담당이다. 키가 없거나 담당자가 떠난 경우 타 참가자의 키로 자동 대체하지 않는다. 기존의 명시적인 방장 대신 진행은 그 턴 전체의 담당자를 방장으로 정한다.
- 실제 모델 호출은 기존 로컬 비용 계측 경로를 지난다. 공유받기만 한 기기에 생성 비용을 중복 합산하지 않는다. 방 전체의 미디어 청구서를 서버에서 합산하는 기능은 이번 범위가 아니다.
- 방 음성의 공유 키는 청자의 모델/목소리 설정을 제외한다. 실제 생성 담당자의 설정으로 만들어진 같은 대사는 다른 청자에게도 공유된다. 음성을 끈 참가자는 재생 요청을 만들지 않으며 담당자가 음성을 끄거나 해당 문단에 도달하지 않았으면 새 음성은 대기할 수 있다.
- 외부 API 응답 유실은 미청구 증거가 아니다. 이미 시작한 유료 작업이 실패하거나 담당자가 떠나면 uncertain으로 두며 임대 만료만으로 재구매하지 않는다. 기존 이미지/본문은 계속 읽을 수 있다. 결과가 불명확한 요청의 자동 재생성은 지원하지 않는다.
- 생성 결과의 늦은 업로드는 원래 계정·토큰이 일치하고 아직 running일 때만 허용한다. 다른 멤버, 다른 자산 키, 탈퇴/강퇴한 계정의 업로드는 거절한다.

## iPhone PWA 메인화면

- 라이브러리 헤더 높이에 safe-area-inset-top을 더해 설정·로그아웃 버튼을 상태 표시줄 아래에 둔다.
- 하위 메뉴의 sticky 위치도 같은 높이를 따른다. 가로 회전에서는 좌우 안전 영역을 반영한다.
- 홈 스크롤 영역을 전체 화면에 고정하고, HTML/body 배경과 하단 안전 영역도 라이브러리 색상으로 맞춘다.
- 모바일 버튼의 최소 터치 크기는 44px이다. 확대 금지 viewport 설정을 추가하지 않았다.

## 검증과 한계

- 원본 vendor/visual-novel/public은 수정하지 않았다. 포팅 스크립트 및 통합 어댑터로 연결한다.
- 서버 테스트: 방 모드 고정, 외부/강퇴 계정 차단, 중복 작업, 만료 작업의 과금 재시도 차단, 자산 키 일치, 늦은/중복 업로드, 입력 만료.
- 클라이언트 테스트: 소설/VN 둘 다 채팅 분리, 숨긴 탭 폴링, 스트림 순번, 증분 복구, 공유 저장, 비용 키 격리, 입력 10초, 업로드 응답 유실 시 생성 1회.
- 실제 브라우저의 두 합성 참가자 화면에서 진입, 채팅 버튼, 입력 알림, 공개 본문 읽기, 정본 인계를 점검한다.
- PWA는 390×844/844×390 합성 safe-area 화면으로 점검한다. 물리 iPhone PWA, 실제 4기기 회선, 유료 이미지/음성 제공사의 실시간 대기 시간은 검증하지 않았다. 렉이나 대기 시간이 0이라는 보장은 하지 않는다.
- Muse는 기존 채팅 UI 보존 항목의 독립 체크리스트만 작성했다. 원본 구현·통합·권한·저장 검증은 주 개발자가 수행했다.
