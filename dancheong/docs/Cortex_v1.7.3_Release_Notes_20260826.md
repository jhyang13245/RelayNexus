# Cortex 1.7.3 — Continuity Capsule V3 정밀 무결성 리비전

배포일: 2026-08-26
적용 범위: 독립 Cortex HTML (`/cortex.html`)
Nexus/단청 기본 엔진: 변경 없음

## 분석 결과

1.7.2 로그의 핵심 문제는 본문 품질 하나가 아니라, 완성된 본문을 서버 상태로 옮기는 경계가 서로 다른 추정 규칙에 의존한 데 있었다.

- `가방을 사물함에 넣었다`, `자기 자리로 가방을 내려놓았다`, `왜 방 안은…` 같은 문장에서 물체·비유를 장소 이동으로 오인했다.
- 사용자가 지정한 `가방에서 꺼낸 잡동사니 → 사물함` 역할을 모델이 `가방 → 사물함`으로 바꿔도 대상·출발지·도착지 검사가 분리되어 있어 통과했다.
- 첫 사건 안에서 아직 등장 권한이 없는 다윤·설아가 본문과 장면 상태에 섞였고, 반대로 비공개 인물 이름을 정규화 과정에서 영구 삭제해 실제 등장 시 복구할 수 없는 구조였다.
- 쪽지를 실제로 찢은 본문 뒤에도 대상 없는 범용 파괴 보정문이 추가됐고, 물품 ID·소유·파괴 원장이 서로 다른 참조를 만들 수 있었다.
- 사건 시간은 시각만 비교해 다음 날의 더 이른 시각을 과거로 오인할 수 있었고, 비트가 의미 충족 없이 구조 표기만으로 전진할 여지가 있었다.
- 로그의 V3 필드가 500자와 깊이 5에서 잘리거나 `null`로 바뀌어 런타임 결함처럼 보였다. 실제 V3에도 인물별 목표·감정 근거 혼합, 빈 물리 상태·압력, 잘못된 출처 턴 문제가 있었다.

## 공통 상태 방화벽

- 모든 사건에 `storyDay`, `startTick`, `endTick`을 부여해 날짜와 시각을 하나의 절대 시간축으로 판정한다.
- 사건 시작 전에는 해당 사건의 인물·물품·장소·정답을 작가 문맥과 Capsule에서 차단한다. 서버 내부의 정식 인물 정보는 보존하고, 실제 공개 시점에만 표면 이름으로 투영한다.
- 비트는 본문의 의미 근거가 목표를 충족할 때만 전진한다. 구조 ID 불일치는 의미 역할로 교정하되, 완성된 본문은 구조 표기만으로 폐기하지 않는다.
- 장소 파서는 등록 장소와 명시적 이동 문법을 함께 요구한다. 물체 이동, 소유 표현, 비유, 단순 장소 언급은 현재 위치를 바꾸지 않는다.
- 행동을 `theme/source/destination/completion` 프레임으로 고정해 역할 치환을 검출하고, 잘못된 국소 문장만 결정적으로 교정한다.
- 휴대 물품은 직접 획득 근거가 있어야 추가하고, 보관·반납·분실·파괴 근거가 있을 때만 소유를 해제한다. 동일 물품의 보유·파괴 참조는 하나의 공개 item ID를 사용한다.
- 상태 패치 검증에 실패하면 본문을 재생성하지 않고 해당 상태 패치만 이전 확정값으로 되돌리는 원자 커밋 경계를 사용한다.

## Continuity Capsule V3

- 추가 API 호출 없이 전 턴 확정 직후 결정적으로 생성하므로 집필 경로의 속도를 유지한다.
- 확정 정사, 인물별 고유 목표·직전 행동·감정 근거 블록, 관계 변화, 미해결 약속, 물리 위치·소유·파괴·상태를 분리 저장한다.
- 다음 장면 압력은 근거가 있는 최대 3개만 선택하며, 현재 사건이 시작 전이면 미래 사건 압력을 생성하지 않는다.
- 본문 꼬리는 완결 문장만 보존하고 내부 태그, 구형 범용 보정문, 아직 등장하지 않은 인물 문장을 제외한다.
- 진단·내보내기의 문자열 한도를 1,800자로, 구조 깊이를 14로 늘리고 임의 `null` 주입을 제거했다.
- 저장 후 복원할 때 월드·사건 비트·정사 리비전이 동일한 Capsule만 현재 상태에 재결합하고 전체 V3 검증을 다시 수행한다.

## 실제 로그 회귀

사용자가 제공한 1.7.2의 10턴 본문을 재생성 없이 그대로 재생하는 회귀 픽스처를 추가했다.

- 위치: 해온고등학교 → 계단 → 계단참 → 교실
- 행동 역할: 가방이 아니라 가방에서 꺼낸 잡동사니를 사물함에 보관
- 표기: `<q>` 제거 후 한국어 인용부호 보존
- 인물: 첫 사건에서 박은서·백서현만 장면 권한 유지, 다음 날 시작 전 다윤·설아 차단
- 물품: 쪽지 획득 뒤 실제 파괴 시 인벤토리에서 제거하고 파괴 원장에 동일 ID로 기록
- 본문: 이미 성립한 쪽지 파괴·점프·착지를 보존하고 대상 없는 구형 파괴 보정문만 제거
- V3: 완결 문장, 인물별 목표, 물리 상태, 다음 압력, 저장·내보내기·복원 검증 통과
